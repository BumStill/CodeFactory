## R5 的豁免边界（为什么不是"沙箱内全放行"）

沙箱约束的是**文件写入**，不约束凭据读取、远端动作，也不替用户决定"要不要动别的 checkout"。
因此豁免只在四个条件同时成立时触发：沙箱真的生效、不是破坏性改写、不是远端动作、
命令不落在凭据/远端/跨 checkout 类别（`trusted_git::outside_write_sandbox_scope`）。
初版只判断前三条，网关套件立刻抓出 `gh auth token` 被放行——这条回归用例保留在套件里。

## 信号边界（本轮补强）

`(allow signal)` 过宽：沙箱内进程能给同一用户下任意进程发信号（实测 `(target pgrp self)`
甚至能杀掉沙箱外进程）。现改为 `(allow signal (target same-sandbox))`，并加双向用例：

- `signals_cannot_escape_the_sandbox`：沙箱内 `kill` 沙箱外的 `sleep` 失败（`outside=1`，目标仍存活）。
- `signals_reach_processes_inside_the_same_sandbox`：沙箱内结束自己的子进程成功（`inside=0`），保证 vitest/cargo 不挂死。

## 沙箱内全量 cargo test 的处理办法

macOS 不允许嵌套沙箱：`sandbox-exec` 里再调 `sandbox-exec` 会得到
`sandbox_apply: Operation not permitted`。因此沙箱自身的存在性/边界用例无法在沙箱内跑，
处理方式是**分层执行**，两层都要绿：

1. **宿主侧**跑沙箱自身套件：`cargo test --lib -- trusted_sandbox`（10/10，真实 Seatbelt）。
2. **沙箱内**跑项目测试与真实工作流：矩阵的 `cargo-test` 用例执行
   `cargo test --lib -- config::settings`（真实 cargo、真实编译、真实测试），加 pnpm vitest / build / git / 后台任务 / 浏览器。
   筛掉 `trusted_sandbox` 不是跳过验收，而是因为那批用例本身要在宿主侧建沙箱。

矩阵脚本里这条限制有注释说明，报告 JSON 保留每项真实耗时与输出尾部，便于复核。
