# 会话自动语义命名业务设计

## 问题

新会话当前把首条用户消息按空白取前几个词并截断后直接作为标题。英文输入看起来像一句未说完的命令；中文通常没有空格，结果更接近原文前 40 个字符，而不是摘要。

会话标题会出现在侧栏、顶栏、搜索、Welcome 和用量详情等多个 surface。它既承担“稍后找到这段工作”的导航职责，又比聊天正文更容易被持续展示。直接复制 prompt 会同时造成辨识度低、列表重复和敏感原文外溢。

## 用户价值

- 用户发送首条消息后，可以通过一个稳定、简短的主题名称重新找到会话。
- 标题表达“正在处理什么”，而不是重复“请帮我”“能否”等命令式措辞。
- 标题不会暴露路径、凭据、邮箱、URL、UUID、代码或日志原文。
- 自动命名失败不影响对话；用户仍可随时手动重命名。

## 业务决策

### 标题是导航元数据，不是聊天摘录

自动标题采用“主题 + 预期结果”的名词短语，例如将“新建 session 的名字，要自动进行总结个合理的”概括为“会话自动命名优化”。标题只保留理解任务所需的产品名或技术专名，不承担保存原始需求的职责。

### 稳定优先于持续追热点

新会话只在开头自动命名。成功生成后，不随之后的消息、模型切换或后台状态反复改变；一个会话只有一个稳定身份。用户手动重命名后，自动流程永久让位。

### 隐私边界不能因便利而扩大

命名请求只使用首个有信息量的用户回合，经裁剪、脱敏后发送给该会话已经选择的 Provider。不得为了标题质量切换到另一个 Provider，也不得读取 system/developer prompt、memory、reasoning、工具参数、工具结果、附件正文、cwd 或分支。

### 对话成功高于命名成功

自动命名在后台异步执行，并在正文回合结束、没有已排队下一回合后才调用 Provider，不阻塞正文请求、流式输出或错误处理。正文 Provider 已失败时不追加模型请求，直接使用本地安全 fallback；命名超时或输出不合规时同样 fallback。仍无法形成安全标题时保持“新会话”，失败不弹阻断式错误。

### 额外调用必须可计量

如果语义命名产生额外模型请求，该请求必须进入统一 Usage 计量，能够区分 `session_title` surface。产品不得把命名成本混入正文请求或表现为免费。

## 业务成功标准

- 中文、英文和混合语言样例都产生可区分的主题短语，而不是首条消息前缀。
- 敏感输入测试中，标题对秘密、路径、邮箱、手机号、URL、UUID、长 hash、代码和日志的泄漏率为 0。
- 自动结果迟到时，手动标题被覆盖的次数为 0。
- 命名调用失败、超时或不支持时，首轮聊天成功率和用户可见错误状态不受影响。
- 同一会话在侧栏、顶栏、搜索、Welcome 和用量详情中显示一致标题。

## 非目标与后续风险

- 本切片不自动回填或重命名旧会话。
- 匿名会话继续显示“匿名会话”，不持久化标题，也不额外发起命名请求。
- 本切片不提供“恢复自动命名”按钮；手动重命名后保持人工标题。
- Session 标题不得作为 commit、PR 或 release 标题；交付命名继续以分支、提交和真实 diff 为准。
- `chat_task_segments.title` 和 checkpoint `label` 目前仍可能保存首条消息原文片段。本切片不把它们悄悄纳入 session 标题改动，也不能据此宣称“产品已无原文标题泄漏”；应作为后续 Payload/隐私治理风险单独修复或复用同一脱敏能力。
