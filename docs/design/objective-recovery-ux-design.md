# Objective Recovery Control Plane：UX 设计

## 状态层级

- `正在继续处理`：系统仍持有 objective；等待、退避、重启接管与远端对账都保持这一层级。
- `需要一项核心输入`：一次性列出不可替代缺项，说明补齐后会自动续接，不要求再发“继续”。
- `需要业务决定`：展示互斥选项、推荐项、业务影响与安全默认；只用于无安全默认的不可逆选择。
- `已完成`：仅由 Completion Arbiter 的证据引用触发。

## 消息与重载

候选回复未通过 Arbiter 时不得呈现为最终完成；可以作为低干扰阶段性记录，但同一 objective 卡继续显示 owner、当前阶段和最近可证明进展。刷新或 App 重启后恢复同一卡，不新增一条“重新开始”的任务。

技术 incident 不显示“回复继续/稍后再试/请自行处理”。它显示系统正在恢复、稳定错误码和下一次安全观察；详细失败链默认折叠。只有 core input/business decision 显示用户 CTA。

## 边界

- 已输出或副作用未知：显示“正在核对已发生操作”，禁止宣称自动重放。
- identity mismatch：显示内部一致性修复中，不让用户选择 worktree/PR；零副作用。
- 用户明确取消：objective 终止，不自动恢复。
