# 会话执行治理：UX 设计

## 回合开始

系统不增加模式开关。根据用户语言形成三种隐式契约：

- “分析、解释、审视、不要改”进入只读审视。
- “修复、实现、修改”进入本地实施。
- “提交、开 PR、合并、发布、上线”进入交付。

如果模型请求越权工具，用户只看到一条简短事实，例如“本回合是只读审视，已阻止编辑请求”，不会出现重复确认或隐藏执行。

“继续/可以继续”直接承接最近可执行方案。用户在运行中发送“先执行刚才批准的方案”时，进度面板原位显示“已按用户指令继续实施”，下一轮开放写工具；发送“停止修改，继续分析”则立即收紧后续工具。系统不得回复“请再次明确要求实施”。

## 长任务进度

运行中固定展示一个紧凑进度面板：

- 当前阶段与当前步骤；
- 下一步；
- 等待原因（仅等待时）；
- 已用时间和最后更新时间。

更新原位覆盖。详细审计事件留在“完整过程”，不把每次心跳变成新的聊天气泡。

### 单工具长等待

- 0–30 秒：沿用当前工具类别文案与整回合累计耗时。
- 30–60 秒：活动文案原位刷新为“某类工具仍在运行”，证明执行链仍有 owner。
- 60 秒后：同一进度卡进入 warning tone，并直接显示“某类工具已运行约 N 分钟”；计划存在时也必须在折叠前可见，不能藏在展开区。
- 工具完成或失败后，下一活动/结果原位覆盖心跳；不留下永久“仍在运行”的卡片。

心跳文案只允许使用脱敏类别，不显示完整 shell、路径、URL、附件名、参数或输出。

### 工具放大提醒

达到 40 次工具调用时，在当前回合显示一次黄色提醒：“本回合工具调用较多，系统已要求复用已有证据并收敛剩余步骤。”提醒不使用红色失败语义，不声称任务卡住，也不会要求用户重新授权。相同回合即使继续到 80 次也不重复堆叠提醒。

## 完成与验证不足

- 验证齐全：一个最终结果卡，列结果、证据和交付层级。
- 第一次缺证据：进度面板显示“正在补充 X”，不显示被拒候选。
- 一次恢复后仍不足：一个 `验证未完成` 结果，说明缺什么和下一步；不再循环。

## 子任务重试

一个逻辑任务始终一张卡。卡片显示“第 2 次尝试成功”等摘要；展开后按时间查看每次 attempt、失败码、子会话和 evidence。空 attempt 也显示为失败，不制造空白任务卡。

## 发布真值

状态文案严格对应结构化层级：

- `release_triggered / artifact_published`：已触发发布 / 版本产物已发布。
- `deployment_pending / succeeded`：部署中 / 部署完成，尚未完成线上验证。
- `live_verified`：已上线并验证。
- `blocked`：停在哪一步、是否可恢复、下一步是什么。
- 任何结构门禁拒绝都不得配绿色“任务已完成”结果卡。
