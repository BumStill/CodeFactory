# 端点能力感知自动切换 UX 设计

> 本次上线切片：单行折叠重试、13px 无框切换提示、候选耗尽的自然中文说明与折叠技术
> 详情。结构化“重试原端点/打开端点设置”按钮和“以后默认使用”动作是后续增强；本次
> 不以文字假按钮冒充完成。

## 1. 设计目标

端点故障恢复是对话的一部分，不把页面变成网络诊断台。用户首先需要知道任务仍在
继续；只有恢复失败时，才需要看到端点排除原因和设置入口。

信息优先级：

1. 任务是否仍在继续、已完成内容是否保留；
2. 从哪个 route 切到哪个 route，以及简化原因；
3. 用户是否需要采取动作；
4. HTTP status、provider code、request id 等诊断详情。

## 2. 同端点短重试

短暂故障期间只保留一条可更新状态：

```text
  ◌ ChatGPT 暂时不可用，正在重新连接…
```

- 不连续堆叠“重试 1/3”“重试 2/3”卡片；
- 不在普通文案中显示内部重试预算；
- 状态使用 13px 操作信息字级和低对比颜色，不抢过助手正文；
- 超过数秒仍未恢复时更新同一行，不新增重复 message row；
- 用户可继续向上阅读，状态更新不强拉回底部。

## 3. 自动切换成功

切换开始并成功接管后，在原回合位置显示一句自然状态：

```text
ChatGPT 暂时不可用，已切换到 DeepSeek v4 Pro，继续处理。
```

- 文案包含 source、target 和简化原因；
- 默认无完整边框、无阴影、无大面积 amber/red 背景；
- 可用细小中性图标或 1px 状态线，但不能比最终回复更醒目；
- 状态最终作为低对比历史步骤保留，点击可展开 route attempt 详情；
- 后续 narration、工具证据和最终回复沿用同一对话流，不出现“新任务”分隔。

若首选 route 在同端点自愈成功，可以把状态淡化为：

```text
  ✓ ChatGPT 已恢复，继续处理。
```

## 4. 能力不匹配不得伪装成成功降级

带图片的回合不能切到无 vision 模型，需要工具的执行不能切到无 tool calling route。
这类候选不在主对话逐条闪现“尝试失败”，只在最终候选耗尽详情中解释：

```text
DeepSeek Flash 未尝试：当前回合包含图片，该模型未配置图片能力。
```

如果有候选仅缺少非必需增强能力，例如不支持用户选择的某档 reasoning effort，系统
必须采用已定义且无语义风险的兼容档位并在详情中记录；没有安全映射时排除候选。

## 5. 候选耗尽

最终状态保持普通助手回复，而不是原始错误 dump：

```text
当前可用端点都无法接管这次任务。已经完成的修改和工具结果已保留。

ChatGPT：服务暂时不可用（503）
DeepSeek：本机没有可读取的 API Key
Local：当前回合包含图片，此模型不支持图片

[重试 ChatGPT]  [打开端点设置]
```

- 首行给结论和 preserved work；
- 每个本机候选只给一行可读排除原因；
- “重试原端点”与“打开端点设置”是结构化按钮，支持键盘操作；
- 不显示“请稍后再试”作为唯一解决办法；
- API Key 问题定位到对应 endpoint；ChatGPT OAuth 问题使用“重新登录”文案；
- 展开“技术详情”后才显示脱敏 status、provider code 和 request id。

按钮行为：

- `重试原端点`：创建新的恢复 episode，保持同一 root goal 和已完成 tool outcome；
- `打开端点设置`：打开 Settings/Endpoints 并聚焦故障端点，不自动修改配置；
- 设置修复完成返回会话后，清楚显示“配置已更新，可继续”，不自动重放副作用。

## 6. 不静默修改默认端点

成功使用备用 route 完成任务后，最终回复下方可以显示低优先级建议：

```text
本回合使用 DeepSeek v4 Pro 完成。  [以后默认使用]
```

该动作不是默认选中，不用 modal 打断任务，也不能在普通 failover 中自动执行。用户
没有点击时，设置和下一回合首选 route 保持不变。

## 7. 与工具证据和连续性共存

切换状态遵循自然聊天密度：

```text
我先读取相关配置并复现错误。

  ✓ 读取 · settings.rs
  ✓ 命令 · 复现返回 503

ChatGPT 暂时不可用，已切换到 DeepSeek v4 Pro，继续处理。

  ✓ 编辑 · model_transport.rs
  ✓ 测试 · 18 项通过

修复完成……
```

- route 状态不能被归入“已完成 N 项工具”折叠组；
- 失败切换也不能制造新的用户气泡；
- 每个真实用户回合仍最多一个 `Remember`，仅在最终 assistant 正文；
- 用户取消后立即把状态改为“已停止后续生成”，不再显示正在切换；
- hydration 后顺序、密度和 live stream 一致。

## 8. 视觉与文案

| 状态 | 默认表现 | 禁止 |
| --- | --- | --- |
| retrying | 中性小圆点 + 单行更新 | 多张重试卡、暴露 1/3 |
| switching | 13px 中性状态行 | 红色错误框、全屏 toast |
| switched | 低对比历史步骤，可展开 | 静默切换、伪装成用户选择 |
| exhausted | 普通正文 + 两个明确动作 | 只抛原始 JSON、“未知错误” |
| auth issue | endpoint 名称 + 登录/Key 动作 | 展示 key_ref、token 或 secret |
| capability mismatch | 人类可读能力原因 | 只写“模型不兼容” |

对话正文维持 15px，操作状态 13px，只有时间和静态元数据可使用 11px。浅色和深色
主题均使用语义 token；status、error 和 action 不只靠颜色区分。

## 9. 可访问性

- retry/switch 状态使用 `role="status"` 与 `aria-live="polite"`，同一状态只播报变化；
- exhausted 终态使用可读标题，按钮有完整 accessible name，例如“重试 ChatGPT
  端点”；
- 技术详情用标准 disclosure，展开后焦点不丢失；
- provider 图标必须配文字，不能只靠品牌颜色；
- `prefers-reduced-motion` 下取消脉冲和淡出，状态文案保留。

## 10. 真实 App 验收

- 1366×768 浅色/深色：两次短重试只占一行，切换成功后正文仍为视觉主体；
- 800×600 浅色/深色：source/target 长名称截断但 accessible name 完整，两个失败动作
  不被输入框遮挡；
- ChatGPT 503 → DeepSeek 成功：同一回合自然续写，状态不制造新气泡；
- 全部 route 耗尽：首屏看到 preserved work、候选原因和两个动作，技术 JSON 默认折叠；
- 带图片回合：无 vision 候选从未显示“正在尝试”；
- 工具成功后切换：工具只显示一次，历史 reload 后顺序不变；
- 用户取消：不再产生 route attempt，状态立即停止；
- 默认端点：完成 failover 后设置值不变，只有点击“以后默认使用”才改变。
