# 模型运行时控制面业务设计

## 问题

CodeFactory 当前把四类不同状态混在全局设置里：

- 新会话默认使用哪个端点和模型；
- 某个既有会话本轮实际使用哪个端点和模型；
- 端点临时失败时是否允许自动接管；
- 账号凭据是否仍然有效、是否需要用户重新授权。

这会产生一组相互关联的用户问题：

- 在会话里切换端点会改掉全局默认，并影响其它会话；
- ChatGPT OAuth `401` 被合并为普通“凭据或余额问题”，没有轻量恢复入口；
- 自动打开浏览器失败后，授权链接没有显示给用户，流程只能重新开始；
- 每轮发送前读取所有端点凭据，未被选中的 DeepSeek 也可能反复触发系统钥匙串授权；
- 有图片的消息可能被交给不支持图片的模型，再静默移除图片重试。

## 产品决策

### 设置默认值与会话运行时分离

设置页的端点、模型和策略是“新会话默认值”。会话创建后保存自己的
`endpoint_id`、`model_id` 和 `model_policy`，后续在会话顶栏修改只影响该会话。

旧会话升级时迁移为 `fixed`，并绑定升级前能够确定的端点和模型。不能确定端点的旧会话
也不得自动跨供应商，必须显示可修复状态。

### 三种会话策略

- `fixed`（固定）：只使用指定端点和模型。失败时原地结束并给出修复动作，不跨端点。
- `prefer`（首选）：先使用指定端点和模型；仅在尚未产生可见输出、工具意图或副作用，
  且故障可安全重放时，使用兼容候选接管。账号过期不自动绕过，优先让用户恢复账号。
- `auto`（自动）：系统按能力、凭据状态和健康状态挑选兼容路由；实际使用的端点和模型
  必须可见并记入用量与回合记录。

策略、端点和模型在回合开始时冻结为 `TurnExecutionPlan`。运行中切换只作用于下一轮，
不得修改当前请求或自动重放已产生副作用的回合。

### 授权是可恢复产品流程

ChatGPT 登录不再是一个阻塞五分钟、只返回最终账号的按钮调用。开始登录后立即返回：

- `flow_id`
- 同一条 `auth_url`
- 到期时间
- 当前阶段

设置页和历史会话里的恢复提示共享同一个授权流程。界面始终提供：

- 打开验证页面；
- 复制验证链接；
- 取消；
- 到期后重新生成。

自动打开浏览器只是便利动作，不是流程成功的证明。界面不得在没有证据时声称“已在浏览器
中打开”。

### 凭据只在真正需要时读取

每轮只读取首个实际候选的凭据；只有安全切换到下一个候选时才读取下一个。进程内使用
singleflight 和短期缓存，避免同一凭据被并发、重复读取。钥匙串权限问题是结构化状态，
不得伪装成端点限流或余额不足。

macOS 上已经存在于旧钥匙串、但没有可用恢复副本的凭据，在一次明确授权读取成功后生成
用户私有的可用性副本。macOS 默认采用这一“本机可用性模式”：Keychain 保存系统凭据，
同时保留权限为 0600 的本机副本以避免每轮系统授权；设置页必须准确说明存储方式，删除
凭据时同时清理 Keychain、本机副本和进程缓存。

### 能力先于路由

图片、工具、上下文和推理能力在选路前参与资格判断。带图片的回合不能路由给无视觉能力
模型，也不能静默删除图片后重试。图片在会话中的预览与模型能力判断彼此独立。

## 成功标准

- 两个同时存在的会话可以分别固定 ChatGPT 和 DeepSeek，互不改写。
- 会话可在固定、首选、自动之间切换，且文案明确“下一轮生效”。
- ChatGPT 账号过期后，原会话内可直接开始重新授权；自动打开失败时仍可手动打开或复制。
- 未被当前回合使用的 DeepSeek 凭据不会触发系统钥匙串提示。
- `401`、缺凭据、钥匙串拒绝、余额不足、限流和端点故障有不同的可行动提示。
- 带图片的消息只进入明确支持图片的候选；不支持时保留消息和附件并要求用户换模型。

## 非目标

- 不在本切片承诺 ChatGPT device-code 登录；只有后端正式支持时才启用该入口。
- 不自动重放已经流出正文、产生工具意图或执行副作用的回合。
- 不把长期规格、计划或执行状态做成新的常驻产品模块。
- 不把 secret、完整授权 URL、token 或钥匙串错误原文写入遥测、聊天记录或 route journal。
