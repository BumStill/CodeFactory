# 现代 Agent Workbench 业务设计

## 1. 背景与问题

CodeFactory 已具备会话、结构化计划、后台委派任务、Git 交付、用量与上下文等能力，但这些能力当前以多条状态栏、局部卡片和 Markdown 叙述并列出现。用户看到的是“日志阅读器 + 若干工程状态插件”，而不是一个可以快速监督、纠偏和验收的 Agent 工作台。

主要业务问题不是缺少装饰，而是：

- 当前回合、后台作业、交付链和待发消息使用不同状态语言，用户难以判断“现在在做什么、为什么停住、下一步该做什么”；
- CI 通过、已合并、已发布和已验证上线没有形成不可混淆的层级；
- 正文、证据、上下文与输入区都在争夺注意力，主要任务不够突出；
- 9–10px 文字、近似灰底和大量分割线使信息密集但不易扫描；
- 真实 Workspace 与旧 acceptance 组件存在分叉，测试可能证明用户看不到的界面。

截图右下角机器人由外部系统覆盖，不属于 CodeFactory，本设计不把它作为品牌资产、导航入口、反馈入口或布局约束。

## 2. 产品目标

把 Workspace 演进为现代、可信、可监督的 Agent 工作台：

1. 用户 5 秒内能看出当前项目、模型、任务阶段、阻塞原因和下一步；
2. 用户不阅读完整日志，也能分辨当前回合、后台作业、交付与待发消息；
3. 结果、证据和完整过程分层呈现，默认界面安静，失败与待批准自动突出；
4. `release` 永远不被描述成 `live`；只有 live verifier 通过才能称为“已验证上线”；
5. 输入区始终是下一步操作中心，运行中可纠偏、排队或停止；
6. 现代感来自一致的表面层级、排版、状态语义和微交互，不依赖渐变、发光或装饰性动画。
7. 宽屏右侧空间只在存在真实辅助上下文时出现，不能留下像加载失败一样的无标题空白。

## 3. 核心用户任务

| 用户问题 | CodeFactory 必须提供的答案 |
| --- | --- |
| 当前正在做什么？ | 当前 root turn 的阶段、当前步骤和下一步 |
| 后台还有什么？ | delegated jobs 的运行、失败、待处理与验收状态 |
| 为什么停住？ | 具体 blocker、影响范围和可执行恢复动作 |
| 代码交付到哪了？ | PR、CI、合并、release、live verification 的真实最远状态 |
| 我接下来怎么干预？ | composer 中可见的引导、排队、停止、附件与权限/环境 |
| 结果是否可信？ | 完成度、修改、验证、失败/等待边界和完整证据入口 |

## 4. 产品决策

### 4.1 四套真相源保持独立

当前回合、后台作业、Git 交付和消息队列不能合并为一个虚假的“大任务状态”。它们共享状态词、颜色、图标和 disclosure 规则，但继续读取各自真实数据源。

### 4.2 结果快照是回复 footer

最终回复仍是主答案。结果快照只作为紧凑 footer，总结状态、完成步骤、证据与边界；展开后查看证据或过程，不复制第二份答案，不切换成 dashboard。

### 4.3 release 与 live 分离

`through_release` 的业务含义是创建并确认正式 release artifact，不代表部署成功或 live verifier 通过。当前没有 `through_live` 设置，因此设置、顶栏和结果中都不得写“发布上线”。

### 4.4 输入区是控制面

附件、队列、模型、思考强度、会话权限、上下文与项目范围围绕 composer 渐进披露，因为这些控制共同决定“下一回合怎样执行”。文件类型不占用 placeholder；正常 context 使用中性色圆环，达到风险阈值后才升级为 warning/danger。会话/今日累计 Token 进入圆环详情，不与当前 context 百分比混为一谈。

### 4.5 右侧工作面需要仲裁

任务活动、Git 详情、交付详情、证据检查器、文档和按需浏览器属于同一“辅助工作面”资源。它们必须由单一 pane arbiter 仲裁；不得同时叠开两个右侧抽屉或让浏览器遮挡任务恢复动作。没有有效内容时辅助面收起并让正文居中；有内容时始终提供标题、加载/错误状态、折叠和关闭入口。

### 4.6 图标优先但不制造猜谜

顶栏正常状态使用“图标 + 数字/对象标识”压缩；只给当前阶段、异常和需要用户动作的状态保留短文字。所有图标按钮必须有 tooltip、可访问名称和可见 focus。模型和权限不再占据顶栏，而在 composer 中一跳可达。

## 5. 演进范围

### 第一批：视觉与任务真相基础

- 建立语义色和现代 surface token；
- 收敛正文阅读宽度与 15/13/11px 字级；
- 结果快照分开表达步骤执行、证据健康与下一动作责任人；
- 正常 context 改为中性进度，阈值才告警；
- composer、queue、context 收敛为一个操作表面；
- 任务抽屉提升可读性，统一状态语义；
- 交付链明确 `release ≠ live`；
- 修正 Workspace 内残留英文和无障碍缺口。

### 本次发布：统一控制面与共享检查器

- 会话侧栏增加搜索、Pin 和 `需要处理 / 运行中 / 待审核 / 最近` 组织；
- 抽取真实 `TaskActivityDrawer`，让 Workspace 与 acceptance 共用；
- 建立右侧 pane arbiter，承载任务、Git、diff、验证、交付与按需浏览器；
- 把模型、思考与权限迁移到 composer，将 context 收敛为圆环详情；
- 顶栏收敛为图标优先的会话/工程/交付/作业状态；
- 清理或迁移 `TaskDashboard`、`ExecutionStream` 等旧 surface。

### 后续深化

- context 详情、自动压缩解释和会话拆分建议；
- Summary / Normal / Verbose 证据密度；
- 更细的证据密度和会话拆分建议；本次键盘、VoiceOver、200% 缩放、Reduce Motion 与高对比仍属于发布门禁，不延后。

## 6. 成功指标

- 5 秒内辨认当前状态、blocker 和下一步；
- 10 秒内从 100 个会话中定位需要处理项；
- 一次点击到达修改与验证证据；
- 正常顶栏不再出现模型/思考/权限三个并列控件，1366px 不换行；
- context 正常时只占一个紧凑圆环入口，累计 Token 一次点击可达；
- 同一时刻最多一个辅助 pane，空内容不占用右侧宽度；
- 未完成结果不出现成功图标或绿色完成语义；
- release 状态不出现“上线”字样，live 未验证时明确显示；
- 1366×768、800×600、375×812 无整页横向溢出，composer 始终可达；
- 正文至少 4.5:1，对象边界与交互状态至少 3:1，桌面核心操作目标至少 36px，窄屏/触控至少 44px。
