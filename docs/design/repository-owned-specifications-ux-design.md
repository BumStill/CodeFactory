# 仓库归属规范与会话内计划：UX 设计

## 体验原则

用户始终停留在当前会话：描述意图、看到 Agent 计划、观察任务执行、审查 diff 和验证
结果。长期规范在背后作为仓库文件参与执行，而不是一个需要用户进入和维护的产品页面。

## Workspace 顶栏

删除：

- 书本图标“规范工作台”。
- 魔杖按钮“拆任务”（由会话内委派替代）。

本切片不重排其他入口；后续顶栏收敛可独立处理。删除后不保留占位、分隔线或空白 tooltip。

## 会话状态

```text
无委派任务
  对话 + 输入 + 常规执行流

Agent 调用 delegate_tasks
  对话
  ┌ 会话执行详情 ─ 运行中 2 / 完成 1 ┐
  │ 任务状态、失败归因、继续/停止/重试 │
  └───────────────────────────────┘
  输入
```

任务面板是当前会话的执行详情，不是导航和内容库；任务为空时完全不出现。

## 仓库规范交互

- Agent 在开始非平凡实现前读取相关 `AGENTS.md`、`docs/specs` 或 `docs/design`。
- 如需要新增长期决策，Agent 在对话中说明原因，然后像修改代码一样修改普通 Markdown。
- 用户从 Git Changes、diff、PR 与证据包审查文档变更。
- 不提供“新建规范”“批准规范”“Issue 创建为规范”等专属按钮。

## 反馈与异常

- 仓库没有 `docs/specs`：不弹空工作台；Agent 可根据项目约定在必要时创建普通目录/文件。
- 只有旧 `.codefactory/specs`：不把它静默当作新权威，也不在运行时擅自搬运；本仓库已跟踪
  文件由显式 Git migration 处理。
- 历史任务带规范标题：仍显示历史来源，点击不会打开已删除的工作台。
- Agent 无需委派：直接在会话执行，不制造单任务任务树。

## 实地验收

- 1366x768：顶栏没有书本/拆任务，Git、检查点和设置仍可点击且不位移重叠。
- 窄窗口：删除入口后模型、Git 和输入主路径仍可用，无横向遮挡。
- 成功路径：复杂请求触发 `delegate_tasks`，会话执行详情出现并更新。
- 边界路径：简单请求不触发委派，工作区保持纯对话；远程 Issue 页面不出现“创建为规范”。
