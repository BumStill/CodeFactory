# 浏览器会话治理：业务设计

## 问题与目标

CodeFactory 的 agent 可以通过 `bash` 启动浏览器自动化。若自动化命令在 `close` 前报错或任务被取消，后台浏览器会继续运行，造成 CPU、内存和图形资源长期占用。

目标是让 CodeFactory 内发起的浏览器自动化具备明确所有者、可见状态和可恢复清理；用户不必记住 shell 清理命令。

## 用户价值

- 自动化完成、失败、取消或应用退出后，后台浏览器不会静默遗留。
- 用户能看到某个任务是否仍持有浏览器会话，并可结束它。
- 长任务不被固定超时误杀；只有失去心跳的会话才会被回收。

## 范围和边界

本期覆盖 CodeFactory 自己创建的 Playwright CLI 会话。普通 Chrome、用户手动启动的浏览器、以及其他应用创建的自动化不由 CodeFactory 结束。

## 验收

1. CodeFactory agent 不再通过 `bash` 直接启动 Playwright CLI；必须使用原生受管工具。
2. 受管会话有任务归属、租约与状态。
3. 正常结束、失败和取消均关闭会话；应用异常退出后下一次启动回收过期会话。
4. 用户能看到并手动结束正在运行的会话。
