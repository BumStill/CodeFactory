# 会话连续执行与自然工具证据 UX 设计

## 1. 设计目标

页面首先是一段人与助手共同完成工作的对话。系统活动自然嵌入对话，不把聊天切换成时间线、工作流看板或结果卡片。自适应只发生在密度、折叠和强调层级上。

阅读优先级为：

1. 用户目标；
2. 助手正在判断什么、最终得出什么；
3. 支撑判断的工具证据；
4. 耗时、token 等辅助信息。

## 2. 正常执行

助手叙述与成功证据沿同一左边界排列：

```text
我先确认这次停止是界面问题还是执行链路中断。

  ✓ 搜索  · agent loop 的终态处理
  ✓ 读取  · policy.rs

问题已经定位：内部执行分段被错误当成了任务终点。

  ✓ 编辑  · policy.rs
  ✓ 测试  · 12 项通过

修复完成。达到内部检查点后会自动续跑，不会再静默停止。
```

成功工具行：

- 不画完整矩形外框，不使用阴影；
- 高度 24–28px，图标、动作、摘要和状态在一行；
- 字号只保留两级：对话正文 15px、操作信息 13px；仅时间和静态状态允许 11px，禁止 9–10px 正文；
- 正文为主要对比度，成功证据只降低颜色对比度，不再靠过小字号制造层级；
- hover/focus 时才出现轻背景，整行可展开；
- 文件产物入口留在同一行尾部，不另造第二张卡。

## 3. 长执行自适应

短执行按原顺序展示每条证据。运行中的当前回合始终保持连续阅读线，不因 segment 数量超过固定阈值而隐藏较早过程。相邻三个及以上例行成功项仍可在原位置聚合：

```text
  ✓ 已完成 6 项检查  · 读取 3 · 搜索 2 · 命令 1   展开
```

- 折叠不命名“阶段”，除非助手正文已经自然说明阶段；
- 当前 root turn 运行中不显示“展开较早的执行过程”，较早叙述、失败和工具证据保持原顺序可见；
- 回合进入 completed、blocked、cancelled 或 failed 终态后，才允许把可收束的较早过程放到原位置的展开入口；
- 当前正在运行的工具永远单独可见；
- 失败、等待权限和用户需要关注的结果永远不并入成功组；
- 展开后仍在原位置显示，不打开侧栏、modal 或新页面；
- 用户向上阅读时，新的 stream 不强拉回底部，沿用 sticky-scroll 契约。

## 4. 运行、失败与中断

运行中是一句轻状态，不是卡片：

```text
  ◌ 正在重新运行相关测试 · 21 秒
```

失败使用 1px 左侧状态线，首行原因直接可见；默认不铺红色卡片背景，摘要限制在可读行宽，完整输出留在展开态：

```text
  ! 测试未通过 · protocol-asset feature 未启用
    查看输出
```

达到内部分段边界时不显示“第 30/80 轮”：

```text
已保存当前进度，正在继续处理…
```

正常接管后这句可淡出为一条历史步骤。若接管失败、task panic 或重启识别到悬空回合：

```text
执行意外中断，已保留完成的修改和工具结果。
继续执行
```

- `继续执行` 是结构化动作，复用原 root goal，不创建含糊的新用户消息；
- 自动恢复正在进行时显示“正在恢复执行…”，不同时提供可重复点击按钮；
- 阻塞必须说明具体需要什么，不使用“达到执行上限”作为理由；
- 取消文案仍是“停止后续生成”，并说明不回滚已完成修改。

## 5. 最终回复

最终回复仍是普通助手正文，包含结论、验证和必要边界。辅助元信息集中在末尾一次显示：

```text
修复完成，达到内部检查点后会自动续跑；异常退出后也能恢复。

用时 8 分 14 秒
```

- 最终回复不再附带手动 `Remember` 控件；
- 中间叙述、工具行、恢复提示、警告和被拒绝候选也不显示记忆入口；
- 没有最终回复而处于 interrupted 时只显示恢复/中断状态；
- 项目记忆由会话后学习自动沉淀，Profile 提供查看和编辑入口。

## 6. 历史恢复密度

历史页面以真实用户回合决定间距，不以数据库 message row 决定：

- 用户回合之间使用 20px 左右间距；
- 同一 assistant turn 内正文与工具证据使用 4–8px；
- 中间叙述只保留自然段间距，不加重复左边框；
- 连续工具组与 live stream 使用相同视觉；
- 恢复产生的技术行被聚合回所属 turn，不制造大块空白；
- “加载更早记录”和截断提示继续遵循超长会话规格。

## 7. 颜色与状态

| 状态 | 表现 | 禁止 |
| --- | --- | --- |
| success | 中性低对比文字 + 小型成功图标 | 黑色全边框、绿色大底色 |
| running | 中性蓝/强调色小圆点 + 文案 | 无限旋转作为唯一信息 |
| permission | 浅 amber 左线/背景 | 与普通成功同色 |
| error | 1px 浅红左线 + 限宽首行原因 | 大面积红底、只给红图标、不写原因 |
| interrupted | 中性提示 + 明确恢复动作 | 假装仍在运行、空白停止 |
| completed | 普通助手正文 | 切换到独立结果 dashboard |

浅色与深色主题都必须使用语义 token；禁止依赖缺失的 Tailwind opacity 类回退到不透明深色。

## 8. 可访问性

- 工具证据使用可聚焦 button，accessible name 包含动作、摘要和状态。
- 折叠组声明包含数量；展开后焦点留在触发器。
- live 状态使用 `role="status"` 与 `aria-live="polite"`，只在状态变化时播报。
- error/interrupted 不只依赖颜色；继续动作可用键盘触发。
- `prefers-reduced-motion` 下停用脉冲和淡出，状态文字保持完整。

## 9. 视口与真实 App 验收

必须在 `pnpm dev` 或 `pnpm tauri dev` 的真实界面走过：

- 1366×768 浅色：20 个成功工具调用没有黑框墙，正文仍是第一视觉层；
- 1366×768 深色：成功、运行、失败、权限状态均可分辨；
- 800×600 浅色和深色：工具摘要截断但状态、展开和继续动作可用，无整页横向滚动；
- live stream：短执行与长执行都逐条自然出现，当前活动回合不整体折叠，用户上翻时不强拉到底部；
- terminal transition：同一长回合从运行中进入终态后，较早过程才收束到展开入口；正在执行的内容不得提前消失；
- 历史 hydration：同一 fixture 与 live 视觉一致，间距不随持久化行数膨胀；
- interruption：分段续跑、模拟 panic、执行中退出后重启三条路径均有反馈；
- 自动记忆：聊天气泡无手动入口，安全 project memory 候选由会话后学习写入 `.codefactory/memory.md`。
