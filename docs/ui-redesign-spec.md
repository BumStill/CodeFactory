# CodeFactory UI/UX 重构规格 + 分步实施计划

> 目标:从**功能本质**重审整体布局与交互,让界面随工作状态自适应;并补齐 5 项交互/功能缺口(其中 ③⑤ 是 ChatGPT-OAuth Stage 2 遗留口子)。
>
> 状态:草案,待评审。落地按本文「分步实施计划」逐 PR 进行,PR 描述引用本文对应小节。

---

## 0. 设计原则(贯穿全局)

**「界面是工作状态的函数,不是能力的陈列柜。」**

1. **挣得屏幕**:每个元素靠"对当前工作是否相关"来占位,而非常驻。
2. **由行为触发**:面板/指示由 agent 的真实动作浮现(拆出任务、检索到知识、激活技能…)。
3. **空闲塌缩**:无内容时塌缩成一个小指示(药丸/徽标),而不是空面板。
4. **职责分离**:**配置/管理**归设置与库;**工作区只显示"正在用的"**。
5. **渐进式呈现 + 两种密度**:`快速任务` = 极简(对话+输入+状态),能力按需浮现;`项目` = 更丰富,但**仍状态驱动**。
6. **发现性平衡**:隐藏空面板的同时,靠"设置/库集中陈列 + agent 按需主动提议"保留可发现性。

## 2. 目标布局模型

- **默认:对话居中、全宽**,作为唯一常量与焦点。
- **右缘"上下文 chip 轨"**:按工作点亮 → `任务 ▸` / `📚 来源` / `🛠 技能` / `🧠 记忆`;点开是浮层/侧滑详情;闲着不在。
- **任务**:生成后浮动/可停靠、可折叠、可隐藏;全部完成塌缩成 `✓ N/N`。
- **底部状态条**:`模型 · 思考强度 · 上下文 · 成本` 常驻(功能价值最高)。
- 结果:默认极聚焦,能力随 agent 真实动作浮现。

## 3. 逐元素规格(布局)

> 模板:**功能 / 触发条件 / 呈现形态 / 空闲塌缩 / 归属**

- **任务栏** — 功能:展示自动拆解子任务+状态 / 触发:主任务拆出 ≥1 子任务 / 形态:浮动·可停靠·可折叠面板 / 空闲:不存在;完成后塌缩 `✓ N/N` / 归属:工作区(状态驱动)。
- **连接器** — 功能:外部集成/数据源 / 触发:已配置 *且* 当前用到时在流里亮 `🔌 用了 X`;未用到只在设置 / 形态:chip + 按需浮层 / 空闲:无配置则不显示,agent 需要时主动提议 / 归属:**配置在设置**,工作区只显"在用"。
- **个人知识库** — 功能:本地文档检索(RAG) / 触发:**被检索到时**(回答带来源 `📚 引用:x.md`) / 形态:来源 chip + 详情浮层 / 空闲:折叠为设置入口 / 归属:库管理在设置/库。
- **技能** — 功能:可复用 agent 行为 / 触发:技能激活 / 形态:对话流内徽标 `🛠 code-reviewer` / 空闲:不显"0 技能" / 归属:管理在技能库。
- **记忆增量** — 功能:本次会话学到(会话末自动总结) / 触发:有新增量 / 形态:小计数 `🧠 +N` + 会话末总结卡 / 空闲:隐藏 / 归属:**汇入「我的画像」同一管线**(`src/pages/Profile`)。
- **对话区** — 始终相关 → 默认焦点,**吃满其他面板让出的空间**;收紧轮次间距、作者分组。
- **顶栏** — 模型选择保留(并入状态);主题切换挪设置;`/Users/...quick` 路径弱化(悬停再显)。
- **底部状态条** — 保留并强化;上下文条更醒目(判断压缩/开新会话)。

## 4. 功能项规格(5 条)

> 模板:**现状 / 目标 / 改动点 / 验收**

### ① Quick 多会话(含匿名模式)
- **现状**:单例(§1),全部持久化。
- **目标**:
  - **多会话**:多条并行 quick + 轻量切换(下拉/侧滑选最近),不绑项目/cwd,不做成完整项目。
  - **匿名模式(ephemeral)**:可开一个"匿名快速任务"——其消息**不落库**(仅前端内存),**离开即丢弃**(新建项目 / 新建另一条 quick / 关闭 app 时默认清空、不保留),且**不进记忆/画像管线**(无痕=不学习)、不建检查点/持久附件。给隐私/敏感对话用。**已定决策**:① 匿名会话的 **API 成本不计入** today/month 统计;② 除"离开即清"外,**显式进入匿名时**提供一个「**退出匿名**」按钮。
- **改动点**:`commands/session.rs`(新建 quick、列出 quick;放宽单例)、`commands/chat.rs` 与 `storage`(匿名会话**跳过** message/session 落库,内存态)、记忆/画像总结**排除**匿名会话、会话列表 UI(`Home`/`Chat` 侧栏"最近快速会话" + "匿名"入口与标识)、`stores/chat.ts`、`storage`(普通 quick 目录按会话 id 区分 `~/.codefactory/quick/<id>`)。
- **验收**:① 能新建第二条 quick、切换、各自独立历史,旧单例兼容;② 匿名会话关闭/切走后,DB 与磁盘无残留、画像无新增;成本可计但不绑持久会话(见开放问题)。

### ② 上下键调历史输入
- **现状**:无。
- **目标**:输入框为空 / 光标在首末行时,`↑`/`↓` 翻本会话已发消息;否则不拦截(多行编辑)。
- **改动点**:`components/MessageInput.tsx`(`onKey` 增加 ArrowUp/Down + 历史栈 + 草稿暂存)。
- **验收**:空输入按 ↑ 回填上一条;↓ 回到草稿;多行中光标移动不受影响。

### ③ 真实 context_length(修 Stage 2 口子)
- **现状**:ChatGPT 模型未填 `context_length` → 128K 兜底(§1)。
- **目标**:显示真实上限;成本/压缩判断不再失真。
- **改动点**:`SettingsPage.tsx` `CHATGPT_MODELS` 补 `context_length`(gpt-5.5 等真实值);`agent/context.rs` `context_length_from_id` 增补新模型名识别。
- **验收**:切到 gpt-5.5 时状态条上限为真实值(非 128K);openrouter 模型不回归。

### ④ 排队 / 真·流中引导
- **现状**:有"排到下一轮"(§1),无真·流中注入。
- **目标**:两档明确——(a)**排队**(默认,现有)、(b)**立即插入**(下一段/下一步即生效);并确认 quick 聊天接全排队 UI。
- **改动点**:agent 循环(`agent/mod.rs`)在每段/每步间检查插入队列并并入当前上下文;`MessageInput.tsx`/`QueueBadge.tsx` 增"立即插入"档;核对 `ChatPage` 是否复用 `ExecutionStream` 的 interjection 通路。
- **验收**:流式中排队消息当前响应后执行;"立即插入"在下一段即影响输出;quick 与项目均可用。

### ⑤ codex 思考强度(修 Stage 2 口子)
- **现状**:硬编码 `effort="medium"`,无配置(§1)。
- **目标**:① 会话级快捷档(模型选择器旁 minimal/low/medium/high 切换);② 设置默认(全局或每端点)。
- **改动点**:`config/settings.rs`(默认 effort 字段)、会话模型记忆(`session.reasoning_effort`)、`agent/mod.rs` `call_chatgpt_model` 改为读会话/设置;前端模型选择器旁加控件 + 设置项。
- **验收**:切 high 后请求体 `reasoning.effort=high`;不设时用设置默认;非 codex 端点不受影响(reasoning 仅对 chatgpt 路径)。

## 5. 分步实施计划(逐 PR)

> 每个 PR:一致 PR-first 流程;UX 变更**实地验证**;绿 CI 后 squash 合并 → 自动发版。

**Phase 1 — 快赢 + 补 Stage 2 口子(小、独立、低风险)**
- PR 1.1 · ③ 真实 `context_length`(`fix`) — 最小、纯数据。
- PR 1.2 · ⑤ 思考强度:会话档 + 设置默认(`feat`)。
- PR 1.3 · ② 上下键历史(`feat`)。

**Phase 2 — 会话与交互模型(中)**
- PR 2.1 · ① Quick 多会话(`feat`)。
- PR 2.2 · ④ 真·流中引导 +排队收口(`feat`)。

**Phase 3 — 自适应布局(架构级,价值最高、改动最大)**
- PR 3.1 · 任务栏自适应:有才出现 / 浮动可隐藏 / 完成塌缩(`feat`)— **先做,最高价值**。
- PR 3.2 · 对话吃满 + 顶栏/路径弱化 + 状态条聚拢(`feat`)。
- PR 3.3 · 能力面板(连接器/知识库/技能)→ chip 轨 + 按需浮层;空 → 隐藏/移设置(`feat`)。
- PR 3.4 · 记忆增量 → 小指示 + 会话末总结卡,接入「我的画像」(`feat`)。
- PR 3.5 · Quick vs 项目 两种密度落定(`feat`)。

**Phase 4 — 横切收尾(最后统一做)**
- PR 4.1 · **文案与风格统一**:把各阶段新增的控件/标识(思考强度选择器、ChatGPT「默认/设为默认」、登录卡片、状态条等)做一次统一审视——① 视觉风格与既有组件对齐(避免原生 `<select>` 等突兀控件、间距/字号/配色统一);② **中英文文案统一**(消除中英混杂,定一套术语与语气)。**刻意留到最后**,等所有新 UI 落定后一次性扫,避免反复返工。

**顺序理由**:Phase 1 独立可立即见效且修我自己的口子;Phase 2 改会话/交互骨架;Phase 3 是布局大改、依赖前两阶段稳定;Phase 4 在所有新 UI 定型后统一收口文案与风格。每阶段内的 PR 尽量互相独立、可单独回滚。

## 6. 风险 / 开放问题

- **Quick vs 项目 边界**:多会话后两者如何区分?建议 quick 永不绑 cwd/项目结构,仅"轻量对话流"。
- **隐藏 vs 发现性**:能力面板隐藏后,新用户如何知道有连接器/知识/技能?靠设置/库集中陈列 + agent 主动提议补足。
- **真·流中注入复杂度**:需要 agent 循环支持段间检查与上下文并入;先在 Responses(chatgpt)路径验证,再推广。
- **兼容**:Quick 多会话需兼容旧单例数据;context_length/effort 改动需对非-chatgpt 端点无回归。
