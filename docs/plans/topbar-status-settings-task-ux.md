# 顶部状态栏、任务入口与设置动线优化方案

> 状态：方案草案，未实施  
> 背景：当前工作区顶部栏在一行内展示模型、推理档位、权限、Git、本地变更、交付状态、任务活动和设置入口；截图中信息密度过高，且设置入口位于最右、设置页返回位于最左，用户动线割裂。用户同时指出「待执行」入口功能/语义可能有问题，不能只做视觉压缩。

> 历史说明（2026-08-11）：本草案关于“运行策略继续留在顶栏”的建议已被 `agent-workbench-experience.md` CF-WB-R19/R20 取代。当前权威方案将模型、推理强度和会话权限移入 composer，并将任务/Git/交付/证据/文档/浏览器统一到单一辅助 pane。

## 1. 观察到的现状

基于当前实现：

- `WorkspacePage` 顶部栏直接横排：会话标题、模型选择、思考档位、会话权限、`GitStatusBar`、`WorkspaceDeliveryStatus`、任务活动按钮、设置齿轮。
- `WorkspaceDeliveryStatus` 已经有 drawer 详情，但顶栏 chip 仍暴露较多文本，例如 `PR #309 · CI 通过 · 已合并 · v1.77.3 · 未验证上线`。
- 任务活动按钮只在项目会话且存在 `pending/running/failed` 任务时出现，文案可能是：
  - `模型配置待修复`
  - `需要你处理`
  - `N 个步骤失败`
  - `正在执行 N`
  - `待执行 N`
  - `任务 N`
- `TasksColumn` 内部显示的是后台任务树、验收结果和恢复操作；当只有 pending 且未运行时，文案是「任务已委派，由后台调度器自动执行；若长时间未开始请检查模型配置或重试委派。」这说明顶栏里的「待执行」并不等价于“用户待办”。
- 设置入口是顶栏最右侧齿轮；`SettingsPage` 返回按钮位于页面左上角。入口/出口位置不一致。

## 2. 核心设计判断

### 2.1 顶栏不应该承载所有详情

参考 VS Code、Cursor、GitHub Desktop、Linear、Slack 的做法，顶部栏应该只保留：

1. 当前工作上下文；
2. 有风险或需要行动的状态；
3. 高频切换入口；
4. 全局入口。

长文本详情应进入 hover tooltip、popover 或 drawer。

### 2.2 「待执行」不应作为用户待办文案

当前 `pending` 更多表示后台调度队列，而不是用户必须操作。因此顶栏不建议写「待执行」。

建议把功能定义改为：

- 顶栏入口名称：**任务活动** / **后台任务** / 图标 badge；
- pending 状态文案：**队列中 N** 或 **等待调度 N**；
- 只有 `failed`、`blocked`、`permission`、`model-provider` 才进入“需要你处理”的语义。

### 2.3 设置页应与入口动线一致

如果入口在右上，设置最好从右侧打开或至少右上提供关闭/完成按钮。左上返回适合从左侧导航进入的页面，不适合从右侧齿轮进入。

## 3. 推荐信息架构

顶部栏改为四段：

```text
左侧：会话/项目上下文     中左：运行策略     中右：仓库/交付状态     右侧：活动入口 + 设置
```

### 3.1 左侧：会话与项目上下文

保留现状：

- 会话标题；
- 草稿/独立任务/匿名标签；
- cwd 二级信息。

不建议新增内容。

### 3.2 中左：运行策略组

当前三项：

- 模型；
- 思考档位；
- 会话权限。

建议保留为可点击 chip，但视觉降权：

- 默认灰底/低对比；
- 图标 + 短标签；
- hover 显示完整 endpoint/model/policy 解释；
- 窄屏时可折叠为一个「运行策略」图标或 chip。

示例：

```text
GPT-5.5 · 首选   思考·超高   信任
```

窄屏/拥挤时：

```text
⚙︎ 运行策略
```

点击展开当前三项。

### 3.3 中右：Git + Delivery 状态

#### Git 状态

保留 `GitStatusBar`，但缩短显示：

```text
fix/settings-nav… · 1 change · synced
```

中文：

```text
fix/settings-nav… · 1 变更 · 已同步
```

规则：

- clean：只显示分支 + synced；
- changed：显示变更数；
- conflict/behind/ahead：使用 warning 色；
- 点击打开 Git 面板。

#### Delivery 状态

将顶栏长串改为一个聚合 chip：

```text
PR #309 · 已发布 · 未实地验证
```

或更短：

```text
PR #309 · not live
```

点击后继续使用现有 `WorkspaceDeliveryStatus` drawer 展示完整链路：

- PR；
- CI；
- Merge；
- Release；
- Live verification。

状态优先级：

| 状态 | 顶栏短文案 | 色彩 |
|---|---|---|
| CI failed | `CI 失败` | red |
| blocked / needs user | `需处理` | red/orange |
| auto-merge queued | `等待合并` | yellow |
| CI running | `CI 运行中` | blue + spinner |
| merged, release pending | `待发布` | blue |
| release triggered, no live verifier | `未实地验证` | yellow tail |
| live verified | `已上线验证` | green |

## 4. 任务活动入口方案

### 4.1 功能定位

把现在的「待执行」入口重新定义为：**后台任务活动入口**，不是用户待办。

它承担：

- 查看后台任务树；
- 查看运行中步骤；
- 查看验收结果；
- 处理失败/阻塞；
- 触发重试或回到对话修复。

### 4.2 顶栏显示规则

建议顶栏只显示图标 + badge，默认不写长文案。

示例：

```text
[ListTodo icon] 1
```

hover tooltip：

```text
后台任务：1 个等待调度
```

点击 drawer 后显示完整解释。

### 4.3 文案规则

| 当前任务状态 | 顶栏 tooltip | drawer 文案 | 是否需要用户行动 |
|---|---|---|---|
| pending only | `后台任务：N 个等待调度` | `已委派，等待后台调度器开始。若长时间未开始，请检查模型配置或重新委派。` | 否 |
| running | `后台任务：N 个执行中` | 显示执行中任务、停止按钮 | 否/谨慎 |
| failed repairable | `后台任务：N 个失败，可重试` | `重试失败步骤` | 是，但可自动 |
| blocked model-provider | `模型配置需要处理` | 打开模型设置 + 已修复重试 | 是 |
| blocked permission | `权限需要处理` | 调整会话权限 + 已授权重试 | 是 |
| blocked conversation | `需要回到对话处理` | 回到对话处理 | 是 |

### 4.4 是否保留该入口

建议保留，但降级显示：

- 不再作为顶栏文字 chip 常驻；
- 只有存在 active/pending/failed/blocked 时显示；
- 完成/取消历史不再常驻；
- pending 不使用「待执行」；
- 真正需要用户处理时才突出显示红/黄状态。

## 5. 设置入口与返回动线方案

### 5.1 P0：最小修复

保留完整设置页，但做两点：

1. 设置页右上角增加 `完成` / `返回工作区` 按钮；
2. 左上返回仍保留，但不再是唯一出口。

布局：

```text
← 设置                                      完成
```

这样从右上齿轮进入后，用户能在右上关闭。

### 5.2 P1：设置改为右侧 Drawer

推荐最终形态：

- 顶栏齿轮点击后，从右侧打开设置 drawer；
- 关闭按钮在 drawer 右上；
- 高频设置放在 drawer 内：
  - 模型与供应商；
  - 会话权限；
  - 浏览器会话；
  - Git/交付；
  - 外观；
- drawer 底部提供「打开完整设置」。

优点：

- 入口/出口一致；
- 不打断工作区上下文；
- 与任务活动、Delivery drawer 的交互模型一致；
- 更符合右侧工具入口的用户动线。

### 5.3 P2：命令面板/快速设置

后续可增加一个小 popover：

```text
设置
├─ 模型与供应商
├─ 会话权限
├─ 浏览器会话
├─ Git / 交付
├─ 外观
└─ 打开完整设置
```

高频设置不必每次进入完整页面。

## 6. 推荐实施顺序

### P0：低风险、快速改善

1. 顶栏任务活动入口改为图标 + badge；
2. pending 文案从「待执行」改为「等待调度/队列中」；
3. Delivery chip 缩短为单一摘要，详情进 drawer；
4. 设置页右上增加 `完成`；
5. 保持现有功能不下线。

### P1：结构优化

1. 设置改为右侧 drawer；
2. 模型/思考/权限在拥挤时折叠成「运行策略」；
3. Git 与 Delivery 统一成状态组；
4. 顶栏支持 overflow collapse。

### P2：功能治理

1. 明确「任务活动」不是用户待办；
2. 对 pending 长时间不启动增加诊断：模型配置、调度器状态、后台任务订阅状态；
3. 对真正用户待办另建 `Needs attention` 入口，而不是复用 pending count。

## 7. 验收标准建议

- 顶栏在 1366px 宽度下不换行、不拥挤；
- 任务 pending only 时不出现「需要你处理」或「待执行」误导文案；
- failed/blocked 时顶栏能明确提示行动类型；
- Delivery 顶栏摘要不超过一枚 chip，详情可点击展开；
- 设置从右上进入后，可以在右上退出；
- keyboard focus：打开 drawer 后焦点进入 drawer，Esc 关闭并回到原入口；
- 窄屏下运行策略/Git/Delivery/任务入口有折叠策略，不挤压会话标题。

## 8. 建议结论

推荐采用：

> 顶栏信息分层 + Delivery 聚合 chip + 任务活动图标化并修正文案语义 + 设置右侧 drawer/右上完成按钮。

优先做 P0，先解决当前截图中的拥挤、误导和动线问题；P1 再统一 drawer 与 overflow 行为。
