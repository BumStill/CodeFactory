# Workspace 顶栏系统性重构方案

## 1. 问题定义

当前 Workspace 顶栏把以下不同性质的信息放在同一条横向 flex 行中：

- 会话身份：会话标题、草稿/独立任务/匿名状态、项目路径；
- 模型控制：endpoint、model、模型策略；
- 推理控制：思考强度；
- 执行安全：会话权限 safe/standard/trusted；
- 本地工程状态：分支、变更数、同步状态；
- 远程交付状态：PR、CI、合并、发布、线上验证；
- 后台任务状态：运行、失败、待处理；
- 全局入口：设置。

这些元素的更新频率、风险等级、操作频率和信息密度完全不同，却共享同一视觉权重、同一高度和同一横向空间。结果是：

1. 用户无法快速判断哪些是“当前状态”，哪些是“可修改控制”；
2. 分支、PR、模型等长文本互相挤压，出现截断、横向扩张和响应式换行；
3. 权限和思考强度这类低频控制常驻占位，却没有足够解释空间；
4. Git 与 PR 都是工程状态，却以两个相邻按钮平铺，关系不清；
5. 任务失败/运行等高优先级状态与普通模型选择混在同一层；
6. 设置成为一个孤立齿轮，用户不知道低频工作区能力应去哪里找。

## 2. 设计目标

### G1：顶栏只做“识别当前会话”和“发现状态”

顶栏第一眼只回答：

- 我现在在哪个会话/项目？
- 当前使用哪个模型？
- 是否有需要处理的风险或交付状态？

具体配置和历史详情进入下拉、抽屉或设置页，不再全部平铺。

### G2：同类信息同层，不以实现组件决定布局

布局按用户心智分成四层：

1. **会话身份层**：标题、项目、草稿/匿名标记；
2. **运行控制层**：模型、推理、权限；
3. **工程状态层**：本地工作树与远程交付；
4. **低频入口层**：任务活动、设置。

### G3：高风险状态优先于低频控制

以下状态必须在顶栏或其紧邻区域可见，不得藏到普通菜单：

- 权限请求待处理；
- 模型连接/路由失败；
- 本地工作树有未提交变更；
- PR CI 失败或合并阻塞；
- 后台任务失败或需要用户处理。

正常状态可以压缩为短摘要；异常状态提升颜色、文字和可点击区域。

### G4：支持窄窗口，不依赖无限横向空间

- 顶栏不再 `flex-wrap` 让所有控件自然换行；
- 桌面宽度下采用双行/分区布局；
- 中等宽度隐藏非关键描述，只保留图标、短状态和 tooltip；
- 窄于 980px 时把工程状态迁移到会话正文下方的 Status Strip 或“更多”抽屉；
- 不允许模型名、分支名或 PR 标题撑开主会话。

## 3. 推荐信息架构

### 3.1 桌面宽度：双层 Workspace Header

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [☰ 会话]  会话标题  · 项目名/路径                         [⚙ 设置]          │  身份层
│            ───────────────────────────────────────────────────────────────  │
│ [模型状态卡] [运行安全卡]                 [本地工作树状态] [交付状态] [任务] │  状态层
└─────────────────────────────────────────────────────────────────────────────┘
```

第一行高度约 44px：

- 左：会话侧栏展开/收起、会话标题、草稿/匿名标签；
- 中：项目名或压缩后的 cwd；
- 右：唯一设置入口；
- 匿名退出按钮仅在匿名会话显示，靠近身份区，不与 Git 状态混排。

第二行高度约 36px：

- 左：一个“模型”摘要按钮；
- 中：一个“运行安全”摘要按钮；
- 右：本地工作树摘要、交付摘要、任务活动摘要；
- 各卡片有明确分组间距，异常卡片提升为 warning/danger。

### 3.2 模型状态卡

将 `ModelPicker` 与 `ReasoningEffortPicker` 从两个相邻控件合并为一个“模型”入口：

```text
[chatgpt · gpt-5.6-luna  首选 ▾]
```

点击后打开统一面板：

- 当前 endpoint/model；
- 模型策略：固定 / 首选 / 自动；
- 思考强度；
- endpoint 切换；
- 模型搜索；
- “从下一轮生效”的说明。

这样思考强度不再单独占一个常驻 select，但仍保持一跳可达。DeepSeek、ChatGPT 等不支持 reasoning 的模型只隐藏思考强度段，不留下空位。

### 3.3 运行安全卡

将 `PermissionModePicker` 改成摘要按钮：

```text
[盾牌  会话权限 · 标准 ▾]
```

点击后打开小面板：

- 安全 / 标准 / 信任三档；
- 每档一句可读描述；
- 说明“只影响当前会话”和“从下一次工具权限判断开始生效”；
- 当前运行中有待批准权限时，摘要直接显示“等待批准”，并优先打开权限对话框。

权限不是模型控制，不再与模型 select 直接拼接成无语义的一串控件。

### 3.4 本地工程状态卡

保留 `GitStatusBar` 的信息，但改为固定宽度、短文案、点击进入统一工程抽屉：

```text
[分支  fix/one-click-im…  · 4 个变更  · 已同步]
```

点击后抽屉内使用 tab：

- 变更；
- 提交历史；
- 远程仓库；
- 恢复点。

规则：

- 分支名只在卡片内截断，完整值放 tooltip；
- 变更数为 0 且已同步时降为低强调；
- 有未提交变更、落后 upstream 或冲突时提升颜色；
- “不是 Git 仓库”不在顶栏占据按钮宽度，迁移到会话身份行的项目状态提示或 Git 抽屉空状态。

### 3.5 远程交付状态卡

保留 `WorkspaceDeliveryStatus` 作为独立状态卡，但压缩首屏文案：

正常：

```text
[PR #327 · CI 通过 · 待合并]
```

异常：

```text
[交付 · CI 失败]
```

点击后打开交付详情抽屉，展示：

- PR/MR 及 head SHA；
- CI 检查；
- 合并状态；
- release tag；
- live verification；
- 下一步动作和阻塞原因。

不要把 PR 标题、分支名、CI 细节全部放在顶栏。顶栏只展示当前最重要的一条状态。

### 3.6 后台任务入口

`TasksColumn` 当前已按规格采用紧凑入口，不再恢复常驻任务树。进一步收敛：

- 无任务：不占位，不显示“任务 0”；
- 有运行任务：`正在执行 N`；
- 有失败/阻塞：`需要处理 N`，优先级高于正常状态；
- 点击打开任务活动抽屉；
- 任务入口在第二行最右侧，设置按钮始终位于第一行最右侧。

## 4. 迁移矩阵

| 当前入口 | 目标位置 | 顶栏是否保留摘要 | 迁移理由 |
|---|---|---:|---|
| 会话标题/草稿/匿名 | 第一行身份层 | 是 | 当前上下文必须可见 |
| cwd 完整绝对路径 | 身份层 tooltip / 项目状态详情 | 否，显示项目名 | 长路径不应占用首屏 |
| `ModelPicker` | 统一“模型”面板 | 是 | endpoint、模型、策略、思考属于同一决策 |
| `ReasoningEffortPicker` | 模型面板内 | 否，模型摘要可带当前档位 | 低频控制，不应独占横向空间 |
| `PermissionModePicker` | 统一“运行安全”面板 | 是，显示当前档位 | 安全控制单独成组，避免误触和误解 |
| `GitStatusBar` | 工程状态卡 + 工程抽屉 | 是 | 分支/变更/同步需要同时理解 |
| `WorkspaceDeliveryStatus` | 交付状态卡 + 交付抽屉 | 是 | PR/CI/merge/release 属于一个生命周期 |
| 任务活动 | 第二行状态入口 | 仅异常/运行时 | 低频时不占位，高风险时提升 |
| 设置齿轮 | 第一行最右 | 是 | 唯一低频全局入口 |
| 匿名退出 | 身份层靠近匿名标签 | 是，仅匿名 | 与会话身份同组 |
| Git history/remote/recovery | 工程抽屉 tab | 否 | 低频详情不应常驻 |
| PR 标题、check 列表、live verifier | 交付抽屉 | 否 | 细节应在按需详情层展示 |
| 模型搜索与端点列表 | 模型面板 | 否 | 不应把长列表放在顶栏 |

## 5. 三种响应式布局

### A. 宽桌面 ≥ 1280px

- 双层 header；
- 身份层完整显示项目名；
- 第二行显示模型、运行安全、本地 Git、交付、任务；
- 每个摘要卡有最大宽度，长文本省略；
- 右侧状态卡不得挤压会话标题到不可读。

### B. 中等桌面 980–1279px

- 仍为双层 header；
- 身份层隐藏完整 cwd，只显示项目 basename；
- 模型与运行安全显示短标签；
- Git 与交付卡只显示图标 + 编号/变更数 + 状态；
- 任务无异常时收进“更多状态”菜单；
- 所有卡片保持一行，不依赖 flex-wrap。

### C. 窄窗口 < 980px

- 第一行只保留：侧栏、会话标题、异常徽章、设置；
- 第二行改成横向滚动的 Status Strip，默认只展示异常或当前激活状态；
- 模型、运行安全、工程状态、交付状态都通过可聚焦的摘要按钮进入 bottom sheet / overlay；
- 不让右侧浏览器/文档 pane 与顶栏争夺同一横向空间；
- 输入框、停止、权限确认必须始终可达。

## 6. 状态优先级与显示规则

### P0：必须常驻可见

- 权限待批准；
- 当前回合失败；
- 交付 CI 失败/合并阻塞；
- Git 冲突或工作树未同步；
- 后台任务需要用户处理。

### P1：正常时显示短摘要

- 当前模型；
- 当前权限档位；
- 当前分支和变更数；
- PR/CI 当前状态。

### P2：只在面板/抽屉展示

- 思考强度完整选项；
- endpoint 列表和模型搜索；
- 模型策略说明；
- PR checks 细节、head SHA、release 资产；
- 提交历史、远程仓库、恢复点；
- 任务步骤和验收证据。

## 7. 交互规则

1. 摘要卡统一使用 `button`，不要让 `select` 直接裸露在顶栏；
2. 点击模型摘要只打开模型面板，不立即改变值；
3. Escape 关闭面板并把焦点还给摘要按钮；
4. 各面板只能同时打开一个，避免模型、Git、交付多个浮层叠加；
5. 交付异常和权限待批准具有更高视觉优先级，但不自动抢普通输入框焦点；
6. 运行中的模型请求不因打开状态面板而改变路由；
7. 切换会话时所有摘要立即跟随新会话，不能残留旧会话的 PR/Git 状态；
8. 匿名会话隐藏持久化设置，模型面板仍可显示当前临时模型；
9. 状态文字统一使用用户语言，技术字段放入详情和 tooltip；
10. 完整路径、完整分支、PR 标题均可复制，但不默认展开。

## 8. 实施拆分

### Phase 1：布局骨架与状态卡

- 新增 `WorkspaceHeader` / `WorkspaceStatusRow`；
- 将现有 WorkspacePage header 拆为身份层和状态层；
- 统一卡片宽度、ellipsis、异常优先级、焦点样式；
- 保留原组件数据和回调，先不改变状态来源；
- 增加 1280/1100/900/375 视口结构测试。

### Phase 2：模型与运行安全面板

- 将 ModelPicker 与 ReasoningEffortPicker 合并为 `ModelControlPopover`；
- 将 PermissionModePicker 改为 `SessionSafetyPopover`；
- 保留原有每会话生效语义和 DeepSeek/ChatGPT 能力过滤；
- 增加 Escape、键盘、切换会话和匿名会话测试。

### Phase 3：工程与交付详情

- 把 Git changes/history/remote/recovery 统一为 `EngineeringDrawer`；
- 把 PR/CI/merge/release/live verification 统一为 `DeliveryDrawer`；
- 顶栏摘要只保留短状态，详情保留当前完整字段级证据；
- 增加远程状态不可用、PR 已合并、CI 失败、分支落后等边界测试。

### Phase 4：真实 App 视口验收

在真实 Tauri App 中验证：

- 1440×900：双层顶栏不挤压会话；
- 1280×800：模型、Git、交付、任务均可读；
- 1024×768：无横向溢出，详情入口可达；
- 900×700：状态条降级且输入框可用；
- 375×812：顶栏不横向撑破，权限/停止/设置可达；
- 模型面板、工程抽屉、交付抽屉、任务抽屉互斥；
- 切换会话后状态不串台。

## 9. 验收矩阵

| 场景 | 期望 |
|---|---|
| 普通项目会话 | 两层顶栏，身份清晰，状态摘要分组，无长文本挤压 |
| 模型切换 | 只打开模型面板；endpoint、策略、模型、思考强度在同一面板 |
| 权限修改 | 安全面板显示三档解释，从下一轮生效 |
| Git 有 4 个变更 | 本地状态卡显示分支 + 4 个变更 + 同步状态，点击进入工程抽屉 |
| PR/CI 正常 | 交付卡显示 PR 编号 + CI 状态 + 合并/发布短状态 |
| CI 失败 | 交付卡提升 warning/danger，并提供详情入口 |
| 任务运行 | 显示正在执行 N；无任务不占位 |
| 权限待批准 | 顶栏显示等待批准，权限弹窗优先级最高但不抢输入焦点 |
| 1366×768 | 顶栏无换行溢出，正文和 composer 仍是主视觉 |
| 1024×768 | 长模型/分支/PR 文本截断但可 tooltip/复制 |
| 375×812 | 关键控制可达，状态移入横向 strip 或 bottom sheet |
| 切换会话 | 模型、权限、Git、PR 状态全部刷新，不能串台 |
| 匿名会话 | 不显示持久化 reasoning/session 控制，不留空白占位 |

## 10. 非目标

- 不删除模型、权限、Git、交付或任务能力；
- 不改变模型路由、权限判断、Git 状态采集、交付状态语义；
- 不把所有设置搬进顶栏；
- 不在首轮重做右侧文档/浏览器 pane；它们已经是独立工作区，应只遵循同样的 pane/tab 互斥原则；
- 不用单纯缩小字体解决信息拥挤。

## 11. 推荐决策

采用“**双层顶栏 + 五个摘要卡 + 三个按需面板/抽屉**”：

- 身份层：会话/项目/设置；
- 状态层：模型、运行安全、本地工程、远程交付、任务；
- 按需详情：模型控制面板、工程抽屉、交付抽屉；权限面板属于运行安全卡；任务继续使用任务抽屉。

这是比继续增加横向压缩、继续把标签改短或单纯增加滚动更稳妥的方案：信息仍可发现，但层级、优先级和空间边界清晰。
