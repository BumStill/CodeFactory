# 会话文档路径友好化整改方案

## 问题

会话里出现 `docs/plans/settings-page-consistency.md`、`/Users/.../report.docx` 等文档路径时，当前通常只渲染为普通文本或行内代码：

- 用户看不到文档内容；
- 路径不能点击；
- 相对路径不知道相对哪个项目目录；
- 长绝对路径挤占会话宽度；
- 只有成功写文件的 ToolCallCard 有独立“打开文件”按钮，助手正文中提到的路径没有同等能力。

现状证据：

- `src/components/MessageList.tsx` 的 Markdown `code` 只渲染代码样式，`a` 只处理已有链接；
- `src/components/ToolCallCard.tsx` 仅对 `write_file`、`write_docx`、`write_pptx`、`edit_xlsx` 等成功工具调用提取 `path` 并显示“打开文件”；
- 助手正文中的行内代码路径没有经过文件识别和本地路径解析。

## 推荐体验

### 1. 路径自动变成“文档卡片”

对助手正文中的以下内容做安全识别：

- 行内代码中的相对路径：`docs/plan.md`、`src/App.tsx`；
- `file://` 路径；
- 明确的绝对路径；
- 工具调用成功后产生的文件路径。

默认展示为紧凑卡片，而不是裸路径：

```text
┌──────────────────────────────────────────────┐
│ 文档  Markdown                 settings-page… │
│ docs/plans/settings-page-consistency.md      │
│ [查看文档] [系统打开] [复制路径]              │
└──────────────────────────────────────────────┘
```

显示规则：

- 优先显示 basename + 文件类型标签；
- 次行显示相对项目路径；
- 绝对路径放入 tooltip / 可展开详情，不默认占满一行；
- 文件不存在时显示“文件已不存在”，保留“复制路径”和“重新检查”。

### 2. 点击“查看文档”打开内置预览

按文件类型走不同预览策略：

| 类型 | 默认行为 |
|---|---|
| `.md` / `.txt` / `.json` / `.yaml` / `.toml` / `.csv` / `.rs` / `.ts` 等文本 | 内置只读预览，保留 Markdown/代码高亮；支持复制、系统打开 |
| `.png` / `.jpg` / `.gif` / `.webp` | 内置图片预览，复用现有 `ImagePreview` |
| `.pdf` | 内置 PDF 预览；若当前 WebView 不支持则降级系统打开 |
| `.docx` / `.pptx` / `.xlsx` | 首版使用现有 Office 文本提取能力显示只读摘要/文本，提供“用系统应用打开”；后续再补 Office 页面级渲染 |
| 其他类型 | 不做猜测，直接提供“系统打开”和“复制路径” |

预览应以右侧 drawer 或 modal 打开，避免离开当前会话；标题栏显示文件名、相对路径和“系统打开”。

### 3. 保留并统一工具卡片体验

将 `ToolCallCard` 的“打开文件”能力与正文路径卡片统一为同一个 `FileArtifactCard`：

- 工具成功产生的文件与正文提到的文件使用同一视觉样式；
- 同一消息中重复出现的路径去重；
- 写文件工具卡片可以显示“刚刚生成”；
- 读取/编辑/格式化工具可以显示“已读取”或“已更新”；
- 只展示成功且可解析的路径，错误输出中的随机路径不自动变成可操作卡片。

### 4. 路径解析与安全边界

- 相对路径统一相对当前会话 `cwd` 解析；
- 使用 Tauri 文件命令/现有文件工具确认存在性和类型，不在前端猜测文件是否存在；
- 仅允许本地 `file://`、项目 cwd 下的相对路径、以及工具已返回的受控路径；
- `http(s)` 链接继续按普通外链处理，不混入本地文件卡片；
- 系统打开使用现有 `plugin:shell|open`，失败时给出可复制的完整路径和明确错误；
- 所有操作提供键盘焦点、`aria-label`、Enter/Space 激活和可见焦点样式。

### 5. 不误识别普通代码

首版只自动识别：

1. 行内代码中的路径；
2. 已有 `file://` 链接；
3. 与本轮成功文件工具结果匹配的路径。

不把普通段落中的 `foo.ts`、命令参数、日志中的系统路径全部改成按钮，避免会话内容被过度“链接化”。后续可根据用户反馈增加显式语法：`[查看文件](file:///...)` 或专用 artifact 标记。

## 实施分层

### P0：可点击、可打开

- 新增 `FileArtifactCard`；
- 从行内代码识别项目内文档路径；
- 支持“系统打开 / 复制路径”；
- 接入当前 `cwd` 和路径解析；
- ToolCallCard 改为复用该组件。

### P1：真正可查看

- 新增 `FilePreviewDrawer`；
- 文本/Markdown/代码内置预览；
- 图片复用现有预览；
- 文件不存在、权限失败、读取失败有用户友好状态。

### P2：Office / PDF 体验

- PDF 内置预览或稳定降级；
- DOCX/PPTX/XLSX 调用现有读取能力显示摘要，并保留系统应用打开；
- 预览中显示页码/工作表等来源信息（若读取结果提供）。

## 验证矩阵

1. 助手消息中出现相对 Markdown 路径：显示文件卡片，可预览、系统打开、复制；
2. 路径含空格、Unicode、Windows 反斜杠：解析正确；
3. 文档不存在：不崩溃，不显示假成功，提供复制路径；
4. 生成 `docx` / `pptx` / `xlsx` 后：正文与 ToolCallCard 不重复堆叠，至少可系统打开；
5. 图片附件：继续显示现有内嵌预览，不回退成裸路径；
6. 普通 URL、代码变量、日志路径：不误识别；
7. 键盘操作和屏幕阅读器：卡片按钮可访问；
8. 真实 Tauri App 中验证成功路径与边界路径，不能只依赖 jsdom。

## 验收标准

- 用户看到的不是裸路径，而是带文件名、类型、相对位置和操作按钮的卡片；
- Markdown / 文本文件可在会话内直接查看；
- Office 文件至少能一键系统打开，且有可用的读取摘要入口；
- 所有路径操作失败都有明确原因和复制路径兜底；
- 既有图片附件、ToolCallCard、知识库来源展示不回归；
- 不把普通代码和日志中的字符串大面积误变成链接。

## 推荐实施顺序

先做 P0 + P1，再做 P2。这样第一版就能解决“看不到、点不了”的核心问题，同时避免在首轮引入复杂的 Office 页面级渲染风险。
