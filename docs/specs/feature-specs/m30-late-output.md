# M30：终态之后的迟到输出水位线

## 已批准任务原文

任务：任务结束后迟到的工具结果不能再写进对话（M30 第二段）。第一段（终态摘要后不再继续执行）已在 #570 / v1.82.6 修复；本任务做「迟到结果水位线」。

1. 回合进入终态（完成、失败、取消）时记录一条持久的水位线，即终态的序号或时间。之后才到达的工具结果、流式片段，不得作为新消息追加到对话主线。可以只记入审计或调试日志，或者折叠成一行「终态之后到达的输出已忽略（N 条）」。
2. 新开一轮之后，水位线随之推进，正常输出不受影响。
3. 先写失败测试，用合成时序复现「终态摘要之后 30 秒工具结果到达」；前端改动附 headless 截图。

约束：不改 `.github/` 工作流、场景注册表与校验器；只用合成数据。

## Applicable Harnesses

Spec：本文与 Req 测试映射。Compatibility：复用既有 `turn_settled_at` / `terminal_revision`，旧事件字段兼容。Observation：迟到事件写调试日志而不入主线。Payload：事件字段断言。Viewport：生产组件 headless 浏览器截图。AI Collaboration：任务限定单执行流，不调用 delegate_tasks；合成数据、自验收。Release：只交付合并，不发版；真机验收由编排方发版安装后完成。

## Implementation Notes

- 复用数据库已有持久终态时间及 hydration，不新建 schema。运行时终态 activity 同样建立消息水位线。
- 后端流式事件以可选 `source_root_turn_id` 标注来源；旧事件仍按当前消息兼容处理。带来源的旧回合事件严格按根回合过滤。
- 不引入新的可操作功能，无需新的 GUI/dispatch 操作入口。
- 真机后续验收：安装发布版，结束完成/失败/取消回合，核对摘要后没有迟到工具/文本；再发消息核对输出正常；重开会话核对终态状态保持。

## 验收矩阵

完成/失败/取消 × 工具结果/文本迟到；终态后 30 秒；hydration 后旧回合；steer 多段；新回合正常输出；旧回合迟到不污染新回合；waiting_system 可继续；旧无来源字段兼容。
