# M280：托管工作区混入主 checkout 未跟踪文件；交付 PR 标题取错任务

## 背景与现场

- 2026-11-11 02:40：M275 的托管工作区（状态 `incident`）里出现主 checkout 的未跟踪文件副本：
  `.claude/deferred`、`.codefactory/attachments`、`t1.py`。这些是用户自己的文件，不该进任务工作区，
  更不能被提交。
- #1055（M274 的交付 PR）标题写成了 M272 的标题：交付工具取 PR 标题时取到了别的任务。

## 决定

- 工作区一律从 git 对象（目标分支/提交）建立，未跟踪与被忽略的文件不进入任务工作区。
- 交付只提交本任务自己的改动；工作区里若残留不属于本任务的未跟踪文件，不得被 `git add`。
- PR 标题/正文来自本会话本次交付的任务（当前 objective），不得回退到"最近一次"或别的会话。

## Requirements Traceability

| Req ID | 需求 | 最低证据 |

| R1 | 查清工作区创建/恢复时哪条路径复制了主 checkout 的未跟踪文件，改为只从 git 对象（目标分支/提交）建立工作区，不复制未跟踪或被忽略的文件 | 单测：主 checkout 放入未跟踪文件后新建工作区，文件不存在；生产复制路径被移除或收窄的 diff 证据 |
| R2 | 交付前若工作区存在不属于本任务改动的未跟踪文件，交付工具不得 `git add` 它们（已有保护则补测试证明） | 单测：工作区带外来未跟踪文件时，暂存集合/提交内容不含该文件 |
| R3 | PR 标题/正文必须取自本会话本次交付的任务（当前 objective），不能取最近一次或别的会话；写清原来取错的原因 | 单测：两个会话先后交付，各自 PR 标题对应各自任务；规格实现说明写明根因 |
| R4 | 不改权限判定，不删除用户主 checkout 的任何文件 | diff 证据：权限模块无改动；主 checkout 文件在验收前后一致 |

## Applicable Harnesses

- Spec Harness（必需）：本文件即规格，Req ID 与测试一一对应。
- Compatibility Harness：工作区/交付路径是既有主路径的修复，回归在既有 Rust 测试套件内跑。
- Release Harness：交付走 `ceiling: merged` + 合并队列，不改发版策略。
- Observation Harness：工作区创建与交付事件仍走既有日志与 `execution_workspaces` 记录。
