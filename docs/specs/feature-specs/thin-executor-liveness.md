## 需求
- R1 查明「活着的回合执行者」判定为何失败（例如：只认某张 legacy 表/某种 run 登记、--dispatch 与界面发起的回合登记方式不同、进程内任务未登记、时钟/心跳时间戳单位不一致等），写进 PR。执行者活性必须以**进程内真实存在的回合任务**为准（内存登记 + 启动时为空），不依赖持久化记账。
- R2 心跳与启动恢复：只能对「确认没有活着执行者且最后活动早于 N 分钟」的 running 会话动作；对刚开始（<N 分钟）的回合一律不动。不得因判定不确定而结束会话——不确定时保持原状。
- R3 合并 M134（task-m134-stop-clears-question.md）：终止之后只有新事实能让会话离开 ended；重启恢复不碰 ended 会话。
- R4 测试（先失败）：回合进行中（含 --dispatch 发起、含工具调用期间、含模型请求等待期间）多次运行心跳与启动恢复 → 状态保持 running、回合不被打断；真死掉的回合 → 超过 N 分钟后才恢复；stop 后恒 ended。加一个端到端：发起回合 → 立即触发心跳 tick ×3 → 回合正常完成并给出回答。
- R5 真机（PR 写实测）：在 dev app 中发起只读浏览器任务与读网页任务，期间手动触发心跳（或等一个周期），两者都正常完成。
