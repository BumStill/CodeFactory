# M273：会话自己写完报告就结束时，系统收尾也必须执行

## 规格（原样，来自任务文件）

- R1：查清会话自己结束时，为什么没进入系统收尾，写进规格。
- R2：只要会话有已合并的 PR（`thin_delivery_refs`），无论会话怎么结束（模型写完报告、收尾唤醒、停止以外的其它路径），都要执行一次 M264 的清理和 M259 的逐项核对，并把结果写进结束原因。用户主动停止的会话不受影响。
- R3：清理是幂等的：已经清理过就不重复做，结果照实写。
- R4：M241、M251、M255、M264 的测试继续通过。

## 现场（2026-11-10，v1.115.0，会话 61fd7e13）

- M272 的 PR #1052 合并后，会话自己写完最终报告就结束了，状态是
  `ended / 任务已结束`。
- M264 的系统收尾没有跑：远端分支 `codefactory/objective-a7e3…` 留在远端，
  结束原因也不是 M259 那种逐项核对的说明，编排方事后手动删了分支。
- 会话报告里还写着「合并队列脚本没有删除 head 分支的逻辑，属预期行为」，
  它以为不需要删。
- 对比：由收尾唤醒结束的会话（6064d686、2cbab8ae）都正确删了分支，也写了
  逐项说明。

## R1：为什么自结束的会话绕过了系统收尾

M264 的清理（删本地 worktree、删本地分支、删已合并的远端分支）与 M259 的
逐项核对，都只挂在一个地方：`thin_derive::merged_settlement::settle_merged_sessions`。
这个扫描的候选会话只有两种状态：

```sql
SELECT session_id FROM thin_session_state WHERE state IN ('waiting_wake','running')
```

会话自己结束时走的是另一条路：`derive_state` 在模型写完最终回答后直接投影成
`ended`（`最终回答已完成`，或已合并事实 `PR #N 已合并`）。于是：

1. 状态先落成 `ended`；
2. `settle_merged_sessions` 永远不再选中它，`closeout_all` 没跑，远端分支留下；
3. 结束原因只有一句 `PR #N 已合并`，没有 M259 的逐项事实。

根因不是清理逻辑坏了，而是「哪些会话需要收尾」按状态筛，而状态是由会话自己
写的。系统把「已经结束」当成了「已经收尾」。

## R2：有已合并 PR 的会话，不管怎么结束都要收尾一次

新增判定：会话在 `ended` 状态下，若满足下面全部条件，就仍然属于收尾候选：

- 结束原因不是 `cancelled%`（用户主动停止的会话不受影响，R2 例外）；
- 结束原因里还没有收尾记录（不含 `系统已自动完成收尾` / `收尾已完成` /
  `收尾未核验`）；
- `thin_external_observations` 里已有该会话的合并/关闭事实。

命中后执行与 `waiting_wake` 会话完全相同的一步：

1. `closeout_all`：M264 的本地工作区、本地分支、已合并远端分支清理；
2. `closeout_result`：M259 的逐项核对（合并提交、远端分支、本地改动）；
3. 结束原因改写为「PR #N 已合并；<逐项事实>。系统已自动完成收尾：<清理明细>。」。

触发点：除了启动时那一次扫描，`objective_supervisor` 的心跳每 12 个 poll（约一分钟）
也跑同一次 `settle_merged_sessions`，所以会话在应用运行中自己结束也会被收尾，
不用等重启。

停止路径（`cancelled：用户已停止会话`）在候选查询里就被排除，不会被清理，
也不会被改写原因。

## R3：清理幂等

- 一次成功收尾后，`execution_workspaces` 行被置为 `closed`，结束原因带上收尾
  标记；两者任一都能让下一次扫描不再重复处理。
- 即使被重复调用，`closeout_all` 本身也是幂等的：工作区不存在写「本地工作区
  已不存在」，本地分支不存在写「本地分支已不存在」，远端分支不存在写「远端分支
  已不存在」，结果照实写进原因。
- 探测超时/worker 失败不改变会话状态，留给下一轮安全 tick 重试（系统自动重试/
  自愈），不生成要用户回答的问题。

## R4：既有门禁不回退

M241（无任务才结束）、M251（PR 未关闭不结束）、M255（合并收尾一次预算）、
M264（系统清理）的测试继续通过；本次只扩大收尾候选集合，不改它们的判定。

## 测试

- 真实裸远端 + 真实 DB：PR 已合并、会话以最终报告自结束（状态 `ended`）。
  一次 `settle_merged_sessions` 之后：远端分支已删除、本地 worktree 与分支已
  删除、结束原因逐项写明（先看到失败）。
- 幂等：第二次扫描不再处理该会话（`settled == 0`）。
- 用户停止的会话（原因 `cancelled：用户已停止会话`）不做清理、原因不变。

## 明确不做

- 不改合并队列脚本（head 分支由 M264 收尾删除，不是队列的职责）。
- 不给会话新的授权：清理仍只在 CodeFactory 保留命名空间与真实合并事实之内。

## Implementation Notes

- 合并事实的判定用 `thin_external_observations.completed_reason`
  （`%已合并%` / `%已关闭%`），这正是产生 `PR #N 已合并` 的那条记录；
  历史库没有 `merged_at` 列时也不会报错。
- 删除远端分支仍要求 `thin_delivery_refs` 里记着同一 PR 的分支名（M264/R1
  不变），没有记录的会话只会核对、不会删别人的分支。
- 自结束会话的逐项核对在清理之后做，所以事实句描述的是最终状态；为此
  `closeout_target` 在托管工作区已被删除时回退到本次会话记录的 `repo_root`。
