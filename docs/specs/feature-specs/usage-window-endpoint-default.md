# 使用时段改为「服务商默认 + 模型例外」，去掉逐模型重复的规则（减法）

## 背景
- CF-WINDOW（#649/#660）按用户 10-14「最好可以针对每个模型来自定义」实现为 `model_usage_windows` 以 ["endpoint","model"] 为键逐条存规则，但没有服务商级默认。
- 用户 10-18 指出：同一服务商（如 DeepSeek）的忙闲时段对所有模型一样，逐模型存是冗余。实际后果：10-18 把默认模型换成 `deepseek-flash`（V4.1-Flash-1017）时，需要把同一条规则手工复制到 4 个模型名（deepseek-v4-pro / deepseek-flash / deepseek-v4-flash / deepseek-v4-flash-vision-exp）；新模型名若漏配就会绕过闲时限制。

## 需求
- R1 新增服务商级规则 `endpoint_usage_windows: { "<endpoint>": rule }`。判定顺序：模型级规则（若存在）> 服务商级规则 > 无限制。
- R2 迁移：启动时若某服务商下所有模型级规则完全相同，合并成一条服务商级规则并删除这些模型级条目；不完全相同时保留模型级作为例外，并取多数规则作为服务商默认（规格写清取法，或不合并只提示）。迁移前自动备份设置。迁移后实际可用性判定与迁移前逐模型完全一致（测试锁住）。
- R3 本地入口：`set_usage_window` 支持不传 model 表示设置服务商级；`get_usage_windows` 返回每个模型的生效规则与来源（endpoint / model）。
- R4 设置界面：先按服务商设置时段；模型行显示「继承服务商」或「自定义」，可切换。
- R5 写入走应用内存里的权威设置并原子落盘（不要再用「读盘→改→写盘」绕过内存的写法，参见 simplify-phase0-inventory.md §6）。
- R6 测试（先失败）：只设服务商级规则时新增模型自动受限；模型级例外覆盖服务商级；迁移前后判定一致；会话豁免（session override）照旧生效。

## 约束
- 不改变现有用户可见行为（除新增服务商级入口）。合成 fixture，不写生产 DB。授权交付（ceiling: merged）。

## Implementation Notes
- R2 不同规则不合并，界面提示保留模型例外。相同规则迁移时对该服务商中原本未配置规则的已知模型保留 anytime 例外，保证既有模型判定不变；之后新增模型继承服务商默认。已有服务商默认不重复迁移。
- R3 模型传 rule=null 恢复继承；无配置时来源为 none（无限制）。保留无效/未知模型键，不静默丢弃。
- Harness：Spec、Compatibility、Payload、Viewport、Observation、AI Collaboration；本任务只合并，不发版。真实安装版验收由编排方发版后完成。
