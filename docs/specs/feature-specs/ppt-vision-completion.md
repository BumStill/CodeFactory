# PPT 视觉截断与工具后静默结束

## 问题及事实边界
用户截图显示 read_pptx、view_image、再次 read_pptx 均标为成功，助手提到视觉描述截断，随后没有后续文本而输入恢复空闲。截图显示 DeepSeek v4 Flash 与信任模式，但缺少故障设备版本、provider 事件日志及原 PPTX，不能据此证明唯一线上根因。

基线源码存在固定视觉输出预算1200、内联辅助结果未携带终止原因、部分非正常 provider 结束被接受为成功等缺口。本任务修复这些可执行复现的缺口；不修改用户原文件，不混入安全 #1043 或 PM 工作。

## 需求
- PPT-R1：OpenAI、Anthropic、Responses 的截断、未完成及空输出不能当作完整模型成功；部分工具调用不得派发。
- PPT-R2：视觉截断不自动发起第二次模型请求；当前辅助调用缺少完整逐尝试记账，安全地限制为一次请求、45秒总时限，不拼接残缺答案；失败后显式说明并允许继续读结构/OCR。
- PPT-R3：只有完整结果能写视觉缓存；缓存策略显式版本化，旧缓存不被误认为新策略验证过的完整答案。
- PPT-R4：工具成功后的模型异常必须产生用户可见错误/可恢复状态，不以空完成结束、不重放已有工具副作用；覆盖空流、截断、超时、取消及恢复边界。
- PPT-R5：真实合成密集 PPTX 读取、渲染、视觉协议调用、重读验证源字节不变；模型为本地合成协议服务时必须明确标记，不冒充真实provider/认证GUI。

## 验收与治理
先失败再实现；实际生产 provider 解析、内部辅助调用、真实 SQLite 缓存与 AgentLoop 分层验证，独立审查。复用现有测试与场景门禁，不修改可信规则。Applicable Harnesses：Spec、Compatibility、Payload、Observation、AI Collaboration；发布需准确head CI与既有发布门禁。

旧安全候选保持独立。普通 PPT 修复按用户质量门禁达标可交付的授权推进；若实际操作被拒绝，报告准确目标，不绕过或换路重试。

## 本地复核后的收敛
原两次自动请求方案在协议测试中可恢复，但最新主线的辅助文本调用仍是 `billing: None`，截断错误也不保留首请求用量。为避免扩大未记账消耗，当前保留2400输出预算的一次调用；自动模型重试延后到完整账本接线。旧方案日志保留为历史，不作为最终验收。

Responses 仅 `incomplete_details.reason=max_output_tokens` 视为输出额度截断；未知原因或内容过滤均为未完成，不以更大预算重试。空模型内容必须在摘要清理前拒绝，避免清理器把空内容替换为虚假的完成声明。原本正常的 metadata 空答案成功预期改为显式失败；不伪造标题或完成文本。

边界说明：单次限制指每个视觉 route 的 helper 调用；保留既有配置路由间 fallback 与本地 OCR，不新增同路由自动重试或额外预算绕行。既有 helper 持久记账缺口不在本次宣称已解决。

## 补充验收边界（2026-11-17）

成功视觉响应需用完整长文本及末尾标记验证不被工具/缓存截断，配对非空length响应拒绝入缓存；两个分支均执行read_pptx→view_image→read_pptx→可见最终答复。实际原生读取/渲染与合成provider须分层记录，不能把固定文本oracle当作模型正确理解201个元素的证据。保存夹具只复制，不写原件。

普通HLT-001/VIS-001源文件映射不能代替新目标登记。原生渲染测试需要LibreOffice/poppler和显式--ignored正式执行入口；真实provider需合法配置的模型连接及可核验用量记录。失败helper用量持久化仍是已知缺口，不用成功usage字段或无自动重试掩盖。
