# M238：更新排队的判断和用户选择

## 问题
没有任务运行时，界面也提示更新排队，只写「N 项」，用户既不知道在等什么，也没法选择。

## 根因
- 更新任务被后台接手后持有租约，界面下一次检查把它算成 1 项本地工作。
- 终端窗口只要开着就算 1 项，里面没有运行命令也一样。

## 要求
- R1：界面检查排除更新任务自己。真实后台任务继续计入。
- R2：终端只有 shell 下存在子进程才计入。Windows 忽略 `conhost.exe`。无法检查时按忙处理，不能丢掉运行中的命令。
- R3：有真实阻塞时，逐项列出在等什么，并提供「等完成后更新」和「立即更新」。选立即更新前要确认工作会被中断。
- R4：立即更新只跳过「等工作结束」这一项，绑定具体版本和构建，只保存在内存里，重启后失效。安装回执、未知安装结果和构建身份校验不变。
- R5：选等待后，更新窗口缩成右上角小标记，后台继续等，工作结束后自动更新。点小标记重新打开，仍可改选立即更新。等待窗口也可以手动收起。

## 验收
- 单测：`m238_queued_update_does_not_block_itself`、`m238_force_overrides_blockers_only_when_requested`、`a_process_with_a_running_child_reads_as_busy`、`UpdateBlockerChoice.test.tsx`。
- 真实 Windows：无任务、只开空闲终端时，更新不提示有工作在运行；终端里跑长命令时列出终端；选立即更新后完成安装和重启。
