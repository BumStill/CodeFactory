# CF-IAB：内联解释器代码的审批边界

## 问题与范围

Python `-c` 的子进程 argv、别名、拼接和动态调用不能由危险短语黑名单可靠识别；该漏洞早于 M266。M266 又使版本化、绝对路径解释器的载荷可能被当作普通引号数据。修复以 `8789db79` 为初始基线，独立于只读 QA/PM 的 PR #1006。

本切片修复代码准入，不执行报告中的危险载荷，不修改 OS 沙箱、发布流程或可信治理根。脚本文件的既有执行策略、解释器二进制真实性和启动环境不属于内联代码静态证明；不得把本修复称为通用代码沙箱。

## 需求与主路径

- CF-IAB-R1：用户在 safe/standard/trusted 会话请求 shell 工具时，内联解释器代码只有完整落入有界、明确的无副作用子集才可免解释器审批；未知、动态、语法失败、超预算均回退审批。危险样本仅作为分类与准入输入。
- CF-IAB-R2：名称规范化覆盖解释器路径和版本号；参数、组合与嵌套解析必须有界。引号中的搜索模式、普通数据、注释和字面量输出不能因包含危险词误报。现有 heredoc 证明继续由原路径负责。
- CF-IAB-R3：未知解释器代码不能借 trusted 模式、工作区写沙箱或自定义 allow 绕过审批；显式 deny 保持优先。原 turn capability、Git 工作区身份与快照、远端独立授权均保留。
- CF-IAB-R4：生产 Gateway 与实际 AgentLoop 配合合成模型、计数工具后端验收：Ask 尚未回答及 Deny 时工具执行次数为零，明确批准后才允许进入工具后端。载荷不交给真实 shell。
- CF-IAB-R5：八个既有集成目标全部回归，并执行相关权限、分类、治理与场景检查；Windows/macOS 远端证据必须绑定最终 PR head。

## 兼容与验收

保留正常只读命令、字面量输出和已有证明的 heredoc。无法静态证明的复杂内联程序可以新增审批，不能为了维持旧的自动放行而扩展未经证明的字符串启发式。直接 Git 写仍遵守原工作区身份、快照及远端授权，不能与解释器未知状态混称。

集成目标：`m159_trusted_git`、`m177_trusted_local_git`、`m180_readonly_still_prompts`、`m182_trusted_git_denylist`、`m198_trusted_heredoc`、`m207_trusted_git_composition`、`m248_trusted_git_sync`、`m248b_trusted_real_commands`。

Applicable Harnesses：Spec、Compatibility、Payload、Observation、AI Collaboration；Release 仅交接，不包含发版授权。无前端改动，未增加 Viewport 范围。

## 实现边界

共享 shell 结构解析器上限为 32 KiB 输入、16 层结构嵌套、2048 输出段和 8192 步共享遍历预算；内联 shell 递归另限 8 层。审批依据为有限的字面量输出语法，不把 `require`、动态调用或一般表达式当作只读证明。显式输入环境变更与内联解释器组合不免审批，避免安全载荷之前的加载器副作用。

由于旧结构解析器不保留完整引号来源，含 `$` 等展开符的内联文本保守审批，包括一部分实际无害的单引号文本。普通 grep、注释、字面量 print/console.log 和既有 heredoc 正向路径有对照测试；复杂 Node 投影及算术表达式的旧自动放行预期改为明确审批，未删除原样本。

两个新辅助文件仅追加到既有 UI-009 的产品路径映射；registry、targets、required checks 与治理验证器不变。

## 交付边界

独立分支、修复、测试、独立审查、普通推送和草稿 PR；不合并、不启用自动合并或队列、不发版、不改变已发布资产。原生安装版与真实危险载荷执行不作为本轮测试手段；候选保持 `not live`。
