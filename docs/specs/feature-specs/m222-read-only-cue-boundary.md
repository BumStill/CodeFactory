# M222 只读线索的词边界（改写 ≠ 改）

## 现象（v1.91.73，2026-11-04）

用户任务「在测试仓库里追加一行并在本地提交……请逐条、原样执行，**不要改写**、不要合并、不要省略开头的 cd」
被判成 `TurnCapability::ReviewOnly`，整轮所有写操作被
「当前是只读任务，已跳过片段 …」拒绝；改发「保留开头的 cd、照抄命令」就正常。

## 根因（不是缺词，是边界）

`has_hard_read_only_directive`（`src-tauri/src/agent/dispatch.rs`）用
`text.contains(cue)` 对 CJK 线索做**子串**匹配：

- `不要改写` 含 `不要改` → 命中「不要改」；
- `不要改名` 同理命中；
- 唯一的排除逻辑是 `别{cue}`，只能覆盖「别不要改」这种不存在的写法。

CJK 没有分词空格，所以「动作词」的子串命中会把**长词的前缀**当成完整动作：
`改写 / 改名 / 改口` 是一个词，`改` 只是它的第一个字；`执行顺序` 里的
`执行` 是名词性词缀。只读判定读取的是「禁止一个动作」的指令，动作必须是
完整的词，否则一句话里的普通搭配就会把整个回合降成只读——而推断出的只读是
**不可恢复**的（同一轮里没有任何后续消息能把它升回来）。

## 设计

### R1 动作词必须是完整的词

线索被拆成「否定前缀 + 动作词」，动作词取 `改 / 修改 / 执行 / 实现 / 动`。
命中之后看**紧接着的下一个字符**：

1. 到消息结尾 → 完整词（`先别修改`、`不要实现`）；
2. 非 CJK（标点、空格、ASCII、数字）→ 完整词（`不要改。`、`don't change it`）；
3. 是 CJK 且起头一个**宾语名词**（代码 / 文件 / 仓库 / 项目 / 命令 / 测试 /
   文档 / 配置 / 分支 / 任何 / 这个 …）→ 完整词（`不要改代码`、`先别动代码`）；
4. 其余 → 是长词前缀（`改写`、`改名`、`执行顺序`），**不算**只读指令。

第 3 条正是 R1 说的「动作的对象是代码或仓库」：宾语表是**名词**清单，
不是往只读词表里塞例外词——`不要改写` 之所以放行，是因为 `写` 不是 `改`
的宾语，而不是因为有人把 `不要改写` 加进了白名单。

方向性取舍：判错的代价不对称。漏判只读 → 回合保留写权限（用户下一条消息仍可
收回）；误判只读 → 整个回合不可恢复地失去写权限。所以边界规则向「完整词」倾斜。

### R2 推断的只读只约束它圈定的范围

同一条消息里出现**未被否定的**写/提交谓语（追加、提交、修改、实现、修复、
写入、创建、新增、更新、重构、推送、发布、部署、生成、合并）时，动作词线索
只约束姿态（讨论优先），不再把回合降成 `ReviewOnly`。

- 结构化只读（`TurnIntent::structured_read_only`，来自 `delegate_tasks`
  review-only 子代理与验收场景声明）**不受**这条影响，仍然是硬只读。
- 被否定的谓语不算写意图：`只分析，不要提交代码` 仍是 `ReviewOnly`。
- 记忆原则写进规格：**推断出来的只读等于不可恢复，所以推断只能定姿态，
  不能定写权限。**

### R3 回归测试用原文

见 `dispatch.rs` 测试模块 `m222_*`：

- 现场三条消息（含「不要改写」「不要改名」变体）→ `Implement`；
- `只分析不要改代码`、`先别修改，给方案` → `ReviewOnly`；
- 7 条带 `改写 / 改名 / 执行顺序 / 不要合并提交` 的正常任务 → `Implement`。

### R4 拒绝文案给出触发原句 —— 未随本 PR 落地

目标文案：

> 当前是只读任务，已跳过 `bash`：…（触发于：「先别修改，给方案」）

用户能一眼看出是哪句话把自己锁成只读，改口就能恢复。

**未落地原因（阻塞点，不是取舍）**：把触发原句送进 `policy::capability_denial`
必须新增 `RunConfig::review_only_trigger`，而 `RunConfig` 的全部字段都在
`crates/agent-headless/src/main.rs` 与 `src/agent/delivery_scenario_repair.rs`
里被逐字段字面量构造；新增字段必然改动这两个文件。它们目前没有任何场景
`change_patterns` 覆盖，补映射要改 `docs/testing/scenario-registry.json`——
该文件在 `run_scenario_harness_gate.py` 的 `TRUST_ROOT_FILES` 中，候选 PR
改它会被 `scenario-gate-pr` 判为 `trusted scenario gate root cannot self-modify
in a normal PR`。与 M212 / M149 同一处阻塞（见 `m213-silent-turn-progress.md`）。

按仓库惯例外置处理，不夹带在词边界修复里：

1. R4 需要一次 **external governance bootstrap**（用户明确批准）先给这两个
   文件补场景映射，或用不新增 `RunConfig` 字段的方案（由 loop 从
   `LoopInputs` 的用户消息自行推导触发句，需要把只读线索识别下沉到
   `agent-loop`/`agent-core`）单独提交。

本 PR 因此只交付 R1–R3（词边界判定 + 结构化只读不受影响 + 回归原文），
R2 已经覆盖「误判只读在同轮恢复」的主路径。
