# 模型使用时段（CF-WINDOW）

### Requirements Traceability

| Req ID | 需求 | 最低证据 |
| --- | --- | --- |
| CF-WINDOW-R1 | 以**单个模型**为粒度配置「使用时段」（同一端点下不同模型可以各不相同，例如 deepseek-v4-pro 仅闲时、deepseek-flash 任何时间；同一模型出现在多个端点时可分别配置），每个模型三选一：任何时间（默认，保持现状）、仅官方闲时（使用该供应商的预设）、自定义时段（时区 + 星期 + 若干时间段，可选排除节假日）。供应商预设只是填入模型配置的起点，套用后仍可逐个模型修改；配置持久化，升级后保留 | 单测 + 设置持久化集成测试（同端点两模型不同时段） |
| CF-WINDOW-R2 | 时段约束适用于所有自动选择模型的路径：会话默认模型、回落 / 降级、自动恢复后的再次请求、本地派单入口新建会话。不在允许时段内的模型不会被选中；不得只在「降级」这一条路径上生效 | 路由测试覆盖这几条路径 |
| CF-WINDOW-R3 | 提供 DeepSeek 官方预设：高峰 = UTC 01:00–04:00、06:00–10:00，周一至周五，中国法定节假日除外；其余全部为闲时。预设是可更新的数据（不硬编码在路由逻辑里）。节假日表随应用内置并可更新；遇到没有节假日数据的年份时按保守口径处理（工作日按高峰算），并在设置页说明 | 边界测试：09:00、12:00、14:00、18:00（北京时间）前后各一分钟；周末；节假日；无节假日数据年份 |
| CF-WINDOW-R4 | 判定在每次新的模型请求前进行。已发出的请求让它跑完，不中途掐断。下一次请求如果当前模型已经不在允许时段，就按偏好顺序换到允许的模型，会话连续、不丢上下文（包括思考模式模型的回放约束），会话里如实写一行「已切到 X：DeepSeek 进入高峰时段」 | 集成测试：一轮进行中跨过时段边界 |
| CF-WINDOW-R5 | 所有候选模型都不在允许时段（或被 CF-QUOTA 上限挡住）时，任务进入可理解的等待：写明「等 DeepSeek 闲时（18:00 开始）后继续」，以及用户能做什么（在设置里放开时段，或换模型）；到点自动继续。等待不消耗技术恢复次数，不能变成「恢复耗尽」或失败 | 集成测试：注入时钟到点自动继续；恢复计数不变 |
| CF-WINDOW-R6 | 用户在某个会话里手动指定了一个当前不在时段内的模型时，明确提示原因，并给出「本会话忽略时段限制」的一次性选项；不静默改用别的模型，也不静默违反配置 | UI 测试 + 路由测试 |
| CF-WINDOW-R7 | 后台可操作：本地派单入口新增读取和修改使用时段的操作（例如 `get_usage_windows` / `set_usage_window`），与设置页共用同一份配置，写审计日志 | 入口往返测试（真实 socket） |
| CF-WINDOW-R8 | 可观测：每次因时段被跳过或换模型，都在 model_route_attempts（或等价记录）里写明原因 `outside_usage_window`、所用时段规则和下一个可用时间；设置页显示每个模型「现在是否可用、下一次切换时间」 | 记录断言 + 设置页截图 |

### Applicable Harnesses
Spec Harness；Compatibility Harness（未配置时行为与现在完全一致；已有 CF-QUOTA 配置不受影响）；Observation Harness；Viewport Harness（设置页新增区块，窄窗口不溢出）；AI Collaboration Harness。

### 测试矩阵
- 时钟可注入，不依赖本机时区。
- 边界：北京时间工作日 08:59 / 09:00 / 11:59 / 12:00 / 13:59 / 14:00 / 17:59 / 18:00；周六、周日；法定节假日、调休上班日（按节假日表）。
- 路由路径：默认模型、回落、自动恢复后的再次请求、派单入口新建会话、手动指定。
- 与 CF-QUOTA 叠加：GPT 达 80% 上限且 DeepSeek 在高峰 → 进入 R5 等待，提示两个原因及最早可用时间。
- 一轮进行中跨越边界（R4）。
- 未配置任何时段：路由与现在逐字节一致。

### Implementation Notes

- 内置节假日表覆盖 2026 年（国办发明电〔2025〕7 号）。**2027 年的放假安排国家通知尚未发布**：已核实上游镜像 `holiday-cn/2027.json` 返回空 `days`、政府网检索无该年度通知，因此不写入任何 2027 日期，避免把猜测当成官方排期。此时按 R3 的保守口径执行（工作日算高峰），设置页显示「已内置节假日／调休数据的年份」，未覆盖年份按保守口径并写明。
- 判定与预设是数据：`src/lib/usageWindowPresets.json` 为唯一预设源，Rust 侧用 `include_str!` 读同一份文件，路由代码不写死供应商。
- 配置键是 `[endpoint, model]` 的 JSON 元组，避免拼接分隔符造成的键碰撞。
- 请求前判定挂在统一的传输入口（每轮 POST 之前，含自动恢复时的再次请求），因此会话默认模型、回落、自动恢复后的再次请求与派单入口新建会话共用同一条门禁。
- 「本会话忽略时段限制」是一次性的会话内豁免，内存态，不写入配置、不影响其它会话或后续新会话。
